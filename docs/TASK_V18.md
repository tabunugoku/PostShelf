## A. 保存データの整合 (重要)

### A-1. 「未分類」と他のフォルダが同時に付く (`src/shared/storage.ts`)
`addToFolders` と `moveToFolder` は、「未分類」(`INBOX_ID`) を外さずにフォルダを足す。管理画面で、未分類のポストをフォルダへドラッグしたり、まとめて追加したりすると、そのポストが「未分類」にも、そのフォルダにも出る。v15 の仕様 (排他) に反する。排他の処理は、画面側の `folderPicker.ts` にしかない。

直し方:
- フォルダ ID の並びを整える関数 `normalizeFolderIds(ids)` を `storage.ts` に 1 つ作る。規則は次のとおり。
  - 重複を除く。「すべて」(`ALL_FOLDER_ID`) は含めない。
  - 実際のフォルダ (「未分類」以外) が 1 つでもあれば、「未分類」を外す。
  - 何も残らなければ `[INBOX_ID]` にする。
- `setBookmarkFolders` の、いまの入れ子の三項演算子を、この関数に置き換える。
- `mutateBookmarks` が返す前に、変更したポストの `folderIds` をこの関数に通す (`addToFolders` / `removeFromFolders` / `moveToFolder` のすべてに効く)。`moveToFolder` で行き先が「未分類」のときは、ほかのフォルダを外して `[INBOX_ID]` だけにする。
- `importData` は、取り込む内容を書き換えない (バックアップの復元だから)。

### A-2. フォルダを削除すると、所属のないポストができる (`deleteFolder`)
最後のフォルダを削除しても、ポストが「未分類」に移らず、`folderIds` が空になる。そのポストは「すべて」にしか出なくなる。`removeFromFolders` は「未分類」に移すので、動きがそろっていない。

直し方:
- `deleteFolder` で、`folderIds` が空になったポストを `[INBOX_ID]` にする (`ensureInboxFolder` も呼ぶ)。
- すでにできてしまっている、空の `folderIds` のポストと、「未分類」と他のフォルダが同時に付いているポストを、1 回だけ直す。
  - 関数名は `repairFolderIds`。実行の印は、保存データの新しいキー `folderIdsRepaired` (真偽値)。スキーマの版 (`SCHEMA_VERSION`) は上げない。
  - どの公開関数も最初に呼ぶ `ensureMigrated` の流れに乗せる。直す対象が 0 件なら、書き込まずに印だけを付ける。
  - 直す内容は `normalizeFolderIds` と同じ。ポストの件数、`tweetId`、`savedAt`、`snapshot` は変えない。変えたら失敗とし、何も書き込まない (`migrateToV2` と同じ作り方)。

### A-3. 同時に書き込むと、更新が消えることがある
`bookmarks` を、全件まとめて読んで、全件まとめて書いている。自動取り込みの保存 (20 件ごと) と、ポップオーバーや管理画面の保存が重なると、どちらかの変更が消えるおそれがある。保存のキーを 1 件ずつに分ける変更は、データの移行の危険が大きいので、今回はしない。代わりに、重なる時間を短くする。

直し方:
- `storage.ts` の「読んで、変えて、書く」の処理 (`setBookmarkFolders` / `removeBookmark` / `addCollected` / `mutateBookmarks` / `restoreBookmarks` / `deleteFolder` ほか) を、同じ実行環境の中で 1 つずつ順に行う (`Promise` の待ち行列で直列にする)。
- 読んだあと、書くまでの間に `await` を挟まない。具体的には、`ensureInboxFolder` を、`readMap` より前に呼ぶ (`setBookmarkFolders` と `addCollected` は、いま読んだあとに呼んでいる)。
- 別の実行環境 (x.com のタブと管理画面) の間の完全な排他は、今回はしない。`docs/PLAN.md` か `storage.ts` の冒頭に、「残る危険と、キーを分ける案」を数行で書いておく。

### A-4. 自動取り込みが、毎回すべての保存済みの ID を読む
`readVisible` が、スクロールのたびに `getSavedIds()` を呼ぶ。保存件数が増えると、2〜4 秒ごとに全件を読むことになる。

直し方:
- `AutoCollector` は、取り込みの開始時に 1 回だけ読み、そのあとは、自分が保存した分を足して使う。
- `onDataChanged` で、他の場所の変更があったときは、読み直す。ただし、自分の保存で起きた変更では読み直さない (印を付けて見分ける)。

## B. 自動取り込みの動き (`src/content/autocollect.ts`)

### B-1. 「15 分後に再開する」の予約が、表示に残ることがある
予約の時刻に、タブが非表示だと、`resume()` が何もせずに終わる。そのとき `resumeAt` が消えず、「◯時に再開します」が出たままになる。

直し方: `resumeLater` の中で、`resume()` が `false` を返したら、`resumeAt` を消して、状態を出し直す (止まったままで、「再開」を押せる)。テストを足す。

### B-2. 保存に失敗した分の数え方
失敗した分は、次の保存 (`seq` 全体を渡している) で、自動的にもう一度保存される。それなのに、すぐ「失敗」に数え、取り込み件数からも引いている。表示の件数が、実際より少なくなる。

直し方:
- 保存に失敗した分は、`pending` に戻して、次の保存で再送する。
- 「失敗」に数えるのは、一時停止・停止・完了の保存でも保存できなかった分だけにする。

### B-3. 複数のタブで開いているとき
x.com のタブを複数開いていると、全部のタブが、保存してある取り込みの状態 (`adopt`) を引き継ぎ、再開などの命令にも、全部が反応する。ウィンドウが 2 つあると、同じアカウントを同時に取り込むことがある。

直し方:
- 取り込みを動かしているタブを、保存データの取り込みの記録 (`collectRun`) に `owner` (タブごとに作る乱数の ID) として残す。
- `adopt` は、表示中のタブだけが行う。引き継いだら、`owner` を自分の ID に書き換える。
- 一時停止・再開・停止の命令は、`owner` が自分のタブだけが実行する。ほかのタブは、`collectRun` の `owner` が自分でないと分かったら、自分の取り込みの状態を消して、パネルを閉じる。
- 開始の命令 (`start`) は、すでに `peek` のあとに消している。2 つのタブが同時に `peek` しても 1 つしか始まらないよう、開始のときは、`collectRun` に、開始の ID (`commandId`) が自分の処理済みかどうかを確かめてから始める。
- テストを足す (2 つの `AutoCollector` と同じ保存データを使って、片方だけが動くこと)。

### B-4. 終わりの判定が、実機で外れるおそれがある
終わりの判定は、「`[role="progressbar"]` が出ていないこと」を条件にしている。X が別の用途 (動画の読み込みなど) で同じ属性を出し続けると、終わりと判定できない。「止めない」を選ぶと、いつまでも止まらない。制限の検知 (`error-detail` / `retry`) も、推測のセレクタ。

直し方 (実機で確かめる前提の、安全側の手当て):
- `selectors.ts` の `loadingIndicator` を、ポストの中の読み込み表示 (`article` の内側) を除いた、タイムラインの読み込みに絞る。候補は、メインの列 (`[data-testid="primaryColumn"]`) の直下にあって、`article` の外にあるものとする。
- スクロールしても位置が進まない (`scrollBy` の前後で `scrollY` が増えない) 状態が 3 回続き、新しいポストも出ないときは、読み込み中の表示があっても、終わりとみなす。そのために、`CollectDeps` に `scrollY()` を足す。
- 「止めない」のときも、一度の取り込みの時間に上限 (2 時間) を設け、上限に達したら一時停止にする (理由は、上限の件数のときと同じ画面に出す。文言は `acReasonCap` を流用せず、必要なら新しいキーを 8 言語に足す)。
- `MANUAL_TEST.md` に、次を足す。実機で確かめて、結果を書く。
  - 終わりまで進んだとき、終わりと判定されるか (読み込み中の表示が出たままでも)。
  - `error-detail` / `retry` が、実際の制限の表示に当たるか。当たらなければ、診断情報を取って `selectors.ts` を直す。

## D. 日本語表現の修正 (`_locales/ja/messages.json` と文書)

| 場所 | いまの文言 | 直した文言 |
|---|---|---|
| `acPanelStopped` | 取り込みを終えました | 取り込みを止めました |
| `acSubRunningDate` | $SPEED$で読み込み中。いま $DATE$ ごろの投稿です | 速度「$SPEED$」で読み込み中。いま $DATE$ ごろの投稿です |
| `docs/MANUAL_TEST.md` (10 行目と 222 行目)、`CLAUDE.md` の UI の構成 | 「新しいフォルダ」 | 「フォルダを追加」(ボタン) |
| `docs/PLAN.md` (「+ 新しいフォルダ」の図と説明) | + 新しいフォルダ | + フォルダを追加 |
| `docs/FAQ.md` の見出し | 規約上のリスクについて (正直な説明) | 規約上のリスクについて |

理由:
- `acPanelStopped` は、完了の表示 (`acPanelDone`: 「取り込みが終わりました」) とほぼ同じ文で、止めたのか終わったのか区別できなかった。
- `acSubRunningDate` は、`$SPEED$` に「ゆっくり」が入ると、「ゆっくりで読み込み中」になって不自然だった。
- 「新しいフォルダ」は、v16 でポップオーバーから消えた (入力欄をなくして、「フォルダを追加」ボタンにした)。
- 見出しの「(正直な説明)」は、本文の内容を、見出しで評価する飾りだった。

守ること:
- 他の 7 言語 (en, zh_CN, zh_TW, ko, es, pt_BR, fr) は、同じ意味に直す。特に、`acPanelStopped` は「止めた」ことが分かる語にし、完了の文と区別できるようにする。
- プレースホルダー (`$SPEED$`、`$DATE$`) の名前と数は、変えない。
- キーを増やすのは、B-4 の上限の理由の文言だけ。増やしたら、8 言語すべてに入れる。
- `CLAUDE.md` の「現在のタスク」の行にある、「取り込み) 、」の「、」の前の空白を除き、`docs/TASK_V18.md` を足す。(main では、すでに直してある。マージしたとき、重ならないように確かめる。)
