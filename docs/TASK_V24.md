# TASK v24: 長いポストの全文 (取得と「たたむ / 広げる」)、本文中のリンク

v23 が終わったあとに実施する。保存データには、省略できる (なくても動く) 項目を足すだけにする。既存の保存データは書き換えず、足した項目がなくても、これまでどおり表示する。

## 背景 (ユーザーの報告)
1. X のタイムラインでは、長いポストが「さらに表示」でたたまれる。たたまれた状態で保存すると、PostShelf にもたたまれた分の本文しか入らない。逆に、全文を開いた状態で保存すると、PostShelf の表示では、たたんだ状態が再現できない。
2. 本文に URL やリンクが含まれていても、PostShelf では、ただの文字で、飛べない。

## 1. 全文の取得と、たたむ / 広げる
### 制約と、方針の例外 (ユーザーが許可した。2 回目の決定で、保存した時点で取るに変更)
- X の非公開 API は呼ばない。DOM だけを読む。これは変えない。
- タイムラインのたたまれたポストは、全文が DOM に存在しない (「さらに表示」はポストのページへのリンク)。そのため、全文を取るには、そのポストのページを開く必要がある。
- ユーザーは、「自動で操作しない」という従来の方針の例外を許可した (自動スクロールの例外 (v15) と同じ扱い)。**ポストを保存した時点で**、たたまれたポストの全文を取る。ただし、広げる範囲は次に限る。
  1. 動かすのは、「ポストのページを、裏のタブ (`active: false`) で開いて読んで閉じる」ことだけ。タイムラインの「さらに表示」を押したり、いま見ているタブを移動したり、いま見ているタブに触れたりはしない。自動のスクロールもしない。
  2. 同時に開く裏のタブは 1 つまで。次を開くまで、4〜8 秒のランダムな間隔をあける。
  3. 自動取り込み (ブックマークの一覧から入れるもの) では、1 回の取り込みで全文を取りに行くのは最大 30 件まで。取り込みの実行中は動かさず、終わってから動かす。
  4. X が制限や警告を出したとき (`selectors.ts` の `xError`、v15 の制限の検出と同じ考え方) は、キューを止める。連続で 3 件失敗したときも止める。止めた理由は、設定の画面に表示する。
  5. 設定に、スイッチ「長いポストの全文を取得する」を足す (初期値: オン)。オフのときは、たたまれた分だけを保存する。設定の形への追加は省略できる項目にし、既存の設定は書き換えない。
- `CLAUDE.md` の「守ること」に、この例外を明記する (自動スクロールの例外の書き方に合わせる。「保存した時点で、たたまれたポストのページを裏のタブで開いて読む。間隔・上限あり、設定でオフにできる」)。`README.md` と `docs/FAQ.md` の、X の規約に関する正直な説明にも、この動作を足す (規約違反になり得る可能性は、v15 と同じ書き方で、法的な助言ではないと書く)。初回の案内 (自動取り込みの案内) には足さず、設定のスイッチの説明文に書く。
- 必須の権限は増やさない。`chrome.tabs.create` / `chrome.tabs.remove` は `tabs` 権限なしで使える。もし、権限の追加が必要だと分かった場合は、実装を止めて、理由を報告する (権限は増やさない)。

### 取得の直し方
1. 保存するとき、そのポストが「たたまれた状態」だったかを判定して、保存する (`snapshot.truncated?: boolean`。省略可)。判定は、ポストの要素の中の「さらに表示」のリンク (`data-testid="tweet-text-show-more-link"`。推測で、実機未確認) の有無で行う。セレクタは `src/shared/selectors.ts` に足し、コメントに「未確認」と書く。
2. **全文の取得 (保存した時点で行う)**: `truncated` が真で、設定がオンのとき、保存の直後に、裏方 (サービスワーカー) へ「全文の取得」を依頼する。裏方は、`active: false` のタブでポストのページを開く。そのページの content script が、主役のポスト (URL の `status/ID` と一致するもの) の全文 (`text`、`segments`) を読んで、メッセージで返す。裏方は、受け取ったらそのタブを閉じ、保存してあるポストの `text`、`segments` を更新し、`truncated` を偽にする。ほかの項目 (フォルダ、保存日時など) は変えない。更新は、画面に件数を出さない。
   - 依頼は「取得キュー」に入る。キューは、サービスワーカーが止まっても続きが分かるよう、保存してある `truncated: true` のポストから作り直せる (キューの状態を、別に永続化しない)。
   - 1 件の待ち時間の上限は 15 秒。読めなければ、タブを閉じ、そのポストは `truncated` のままにして次へ進む (同じポストの再試行は、1 時間に 1 回まで)。
   - ユーザーの作業を邪魔しない (前面に出さない、音を出さない、閉じ忘れを残さない)。ブラウザを閉じる、拡張を無効にするなどでタブが残ったときは、起動時に、開いた記録のあるタブを閉じる。
3. **自動取り込み**: 取り込まれた `truncated: true` のポストも、同じキューに入れる (最大 30 件。上の 3)。30 件を超えた分は `truncated` のままにする。設定の画面に、「全文を取得していないポスト: N 件」と、「いま取得する」のボタンを置く (押したときだけ、続きを最大 50 件、キューに入れる。押すと確認を 1 回出す: 件数、1 件ごとに 4〜8 秒かかること、裏のタブが開いては閉じること、規約に関する注意の 1 行)。進み具合と「止める」ボタンも、同じ場所に出す。
4. **機会的な更新**: ユーザーが、ポストの個別ページ (`/ユーザー/status/ID`) を自分で開いているとき、主役のポストが全文で表示されていて、そのポストが保存済みで `truncated` が真なら、同じように全文に更新する (キューを待たない。静かな更新)。
5. 全文を取れていないポストには、管理画面で「全文は X で見る」のリンク (X のポストのページへ。新しいタブ) を、たたんだ本文の末尾に出す。

### 表示の直し方 (管理画面、サイドパネル。ポスト表示と、リスト表示の展開部分)
- 本文は、一定の長さ (目安: 6 行) を超えるとき、たたんで表示する。「さらに表示」を押すと、全文を広げ、「閉じる」でたたむ。X の見た目に近い、文字のボタンにする (スクリーンショットの「さらに表示」の青い文字を参考にする)。
- 広げた状態は、そのポストごとの画面内の状態にする。保存はしない (開き直したらたたむ)。
- たたむ長さは、保存時に X がたたんでいたかには依存しない (X の画面で全文を開いた状態で保存したポストも、PostShelf ではたたんで表示できる)。
- キーボードで操作できるボタン (`<button>`)、`aria-expanded` を付ける。8 言語の文言を足す (「さらに表示」「閉じる」「全文は X で見る」)。既存のキーがあれば再利用する。
- 検索は、これまでどおり、保存してある全文 (`text`) に対して行う。

## 2. 本文中のリンク
### 取得
- 本文の中のリンク (`tweetText` の中の `<a>`) を、順序つきの部品の並びとして保存する (`snapshot.segments?: Array<{ t: 'text'; v: string } | { t: 'link'; v: string; href: string }>`。省略可)。`text` (プレーンな文字列) は、検索と書き出しのために、これまでどおり残す。
- リンクの種類は、URL (外部)、`@メンション`、`#ハッシュタグ`。`href` は、X の画面のリンクの `href` を使う (外部 URL は X の短縮 URL (t.co) になる。実際の URL の展開は、X の非公開 API なしでは正確にできないため、しない)。`@メンション` と `#ハッシュタグ` は、相対リンクを `https://x.com` に補う。
- 画面上の URL は、X が途中で「…」に省略して表示する。表示文字 (`v`) は、画面に出ている文字のままにする。クリック先は `href` なので、省略されていても飛べる。
- `href` は、`https:` と `http:` のものだけ保存する (`javascript:` などは捨てる)。

### 表示
- `segments` があるとき、リンクの部品を `<a>` で表示する。`target="_blank"`、`rel="noopener noreferrer"`。色は、X のリンクに近い青 (配色の変数に合わせる)。ライト / ダークのどちらでも読める。
- リンクのクリックが、カード全体のクリック (ビューアが開く、選択など) と、ぶつからない。リンクを押したときは、リンクだけが動く (`stopPropagation`)。
- `segments` がない古い保存分は、`text` のなかの `https://` で始まり、途中で省略されていない (末尾が「…」でない) URL だけを、同じ方法でリンクにする。「…」で終わる URL は、飛べないのでリンクにしない。
- 保存データの読み込みと取り込み (JSON のインポート) では、`segments` の形と `href` を検証する (不正なら無視して、`text` で表示する)。書き出しの JSON にも、`segments` と `truncated` を含める。
- 初めてリンクを開くとき、X の短縮 URL を経由して、X のサーバーにアクセスが記録され得る。この点を、`docs/FAQ.md` (または README のプライバシーの節) に 1 行書く (PostShelf 自体は外部通信をしない。ブラウザが開くだけ)。

## 守ること
- 必須の権限は増やさない。外部通信のコードは足さない (X のページを裏のタブで開くのは、上の例外の範囲だけ)。タイムラインの「さらに表示」を押す操作や、いま見ているタブの移動はしない。
- 保存データの形は、省略できる 2 つの項目 (`truncated`、`segments`) を足すだけ。既存の項目の意味は変えない。`SCHEMA_VERSION` は上げない。足した項目がない保存分は、これまでどおり動く。
- 本文の表示は、HTML として解釈しない (`dangerouslySetInnerHTML` を使わない)。`href` は検証したものだけ使う。
- 文字列を直接比べているテストは、新しい見た目に合わせて直す。

## テスト
- fixture: たたまれたポスト (「さらに表示」のリンクあり)、全文のポスト、リンク (外部 / メンション / ハッシュタグ) を含むポストを足す。`truncated` と `segments` が期待どおりに取れる。
- 個別ページで、保存済みで `truncated` が真のポストが、全文に更新される。保存されていないポストは、保存されない。`truncated` が偽のポストは、更新されない。ほかの項目は変わらない。
- 6 行を超える本文が、たたまれて表示される。「さらに表示」で広がり、「閉じる」でたたまれる (`aria-expanded`)。
- `segments` のリンクが `<a>` になり、`target="_blank"`、`rel` に `noopener` が入る。`javascript:` の `href` は、表示されない。
- リンクを押しても、カードのクリックの動作 (ビューア、選択) が起きない。
- `segments` がない保存分で、省略されていない URL だけがリンクになる。
- 書き出し → 読み込みで、`segments` と `truncated` が保たれる。不正な `segments` は無視される。

- 全文の取得 (保存した時点): `truncated` のポストを保存すると、取得の依頼が出る。設定がオフなら出ない。`truncated` が偽なら出ない。1 件ずつ、4〜8 秒の間隔をあけて動く (テストでは、待ち時間を差し替えられる)。同時に 2 つ動かない。15 秒で打ち切り、タブを閉じる。連続 3 件の失敗、または `xError` で止まる。いま見ているタブは移動しない (タブの作成は `active: false`)。取得した全文で `text`、`segments`、`truncated` だけが更新され、ほかの項目は変わらない。マニフェストの権限が増えていない。
- 自動取り込みでは、1 回に取りに行くのは最大 30 件。残りは `truncated` のままで、設定に件数が出る。「いま取得する」は、確認を出し、最大 50 件を取り、止めるボタンで止まり、開いたタブが閉じる。取り込みの実行中は、キューが動かない。

## 実機で確認する項目 (`docs/MANUAL_TEST.md` に v24 の節を足す)
- 「さらに表示」のあるポストを、タイムラインでたたまれたまま保存する → 数秒のうちに、裏のタブが 1 つ開いて閉じる。いま見ているタブは、そのまま。PostShelf を開くと、全文になっている。
- 設定のスイッチをオフにして同じことをする → タブは開かず、たたまれた分だけが入り、「全文は X で見る」が出る。
- 自動取り込みで、たたまれたポストが多いとき、取得が最大 30 件で止まり、残りの件数と「いま取得する」が設定に出る。「いま取得する」で進み具合が出て、「止める」で止まる。
- X が制限を出したと思われるとき、止まって理由が出る (起こりにくいので、起きたときに確認する)。
- 全文を取れなかったポスト (裏のタブの取得に失敗したもの) に、「全文は X で見る」が出る。そのポストのページを X で自分で開く → PostShelf を開き直すと、全文になっている。
- 全文を開いた状態で保存したポストが、PostShelf で、たたまれて表示され、「さらに表示」で広がる。
- 本文の URL、メンション、ハッシュタグを押すと、新しいタブで開く。カードのビューアが開かない。
- 「さらに表示」のリンクの属性が、推測どおりか (違えば、`selectors.ts` を直す)。
