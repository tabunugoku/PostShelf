# 追加タスク (v11): 画像・動画のビューアと、画像のキャッシュ

前提: v10 まで `claude/serene-johnson-j5tpe7` で実装済み。続きで作業する (最初に `origin/main` をマージ)。
見た目の基準は `docs/mockups/media-viewer.html` (ビューアと、設定「画像のキャッシュ」の両方。ユーザー確認済みの見た目)。

## 背景 (現状のコードで分かっていること)
- 画像は `snapshot.media` に URL (`img.src`) だけを保存している (`src/content/snapshot.ts`)。manager のカードはその URL を直接 `<img>` で表示している。クリックしても何も起きない
- 動画は `hasVideo` の真偽値だけで、サムネイルも保存していない
- 動画の再生用ファイルは、X の画面から正規の方法で取り出せない (blob / ストリーミング)。X の非公開 API は呼ばない方針なので、動画の再生はしない

## A. ビューア (画像・動画をクリックしたとき)
タブ版とサイドパネル版の manager 共通。
1. 画像
   - クリックで全面表示 (暗い背景、中央に画像、右上に「✕」、複数枚は左右の「‹ ›」と「N / M」、下に「元のサイズで開く ↗」「X でポストを開く ↗」)
   - 表示する URL は、`pbs.twimg.com` の画像 URL の `name=` パラメータを大きいサイズ (`orig`。無ければ `large`) に差し替えたもの。差し替え関数は純関数にして単体テストする。形式が想定と違う URL は、そのまま使う
   - 「元のサイズで開く」は新しいタブ (`rel="noopener noreferrer"`)
   - キーボード: `←` `→` で前後、`Esc` で閉じる。`role="dialog"` `aria-modal="true"`、開いたら閉じるボタンにフォーカス、閉じたら元のボタンにフォーカスを戻す。Tab キーはダイアログの中で循環させる。背景のクリックでも閉じる
2. 読み込み失敗 (元のポストの削除、X 側の URL 変更): 「画像を読み込めませんでした」と理由、「X でポストを開く」、「保存してある小さい画像を表示」(保存済みの URL またはキャッシュ) を出す
3. 動画
   - 保存時に、`<video>` の `poster` 属性 (サムネイルの URL) を `snapshot.videoPoster?: string` として保存する。セレクタ候補は `src/shared/selectors.ts` に追加する (v7-D の `queryFirst`)。取れないときは undefined
   - カードでは、サムネイル (無ければ動画アイコンの枠) に再生マークと「動画」バッジを重ねる。クリックで案内ダイアログ「動画は X で再生します」「X で動画を再生 ↗」(ポストを新しいタブで開く)
   - 古い保存分 (poster なし) は、動画アイコンの枠だけ。特別な移行はしない
4. カード側
   - 画像とサムネイルは `<button>` にする (`aria-label`: 「画像 N / M を大きく表示」)。hover で「拡大」ヒント、カーソルは `zoom-in`。フォーカスリングが見えること
   - 選択モード (複数選択) 中は、クリックで選択を切り替える (ビューアは開かない)。リスト表示のカバー画像、グリッド表示のサムネイルも同じ
   - ポスト表示のカード内のリンクや「…」メニューなど、他のクリックには影響しない
5. i18n: 追加する文言は 8 言語すべて。ja は v8 / v10 の方針 (全角括弧、「自分で」「スマホ」、「判定できないため」などの言い回し) に従う
6. テスト (vitest + jsdom): 画像 URL の差し替え、開閉 (✕ / Esc / 背景)、前後移動と端での循環、フォーカスの戻り、選択モード中はビューアが開かない、読み込み失敗の表示、動画の案内ダイアログ、`videoPoster` の取得 (fixture に `<video poster>` を追加)

## B. 画像のキャッシュ (保存先と最大容量を選べる)
初期値はオフ。保存した画像を PostShelf 側にも残す。動画はサムネイルだけ。
1. 設定 (`src/shared/settings.ts`)
   - `imageCache: { enabled: false; backend: 'idb' | 'dir'; maxBytes: number (既定 1 GB); quality: 'large' | 'orig' (既定 'large'); onFull: 'evict' | 'stop' (既定 'evict') }`
   - 選べる最大容量: 500 MB / 1 GB / 2 GB / 5 GB / 10 GB / 指定 (MB 単位、最小 100 MB)
   - 「設定を初期の値に戻す」(v9-F) の対象に含める。「すべてのデータを削除」(v9-F) はキャッシュも消す
2. 権限
   - 画像サーバー `https://pbs.twimg.com/*` へのアクセスは、`optional_host_permissions` に宣言し、キャッシュをオンにする操作 (ユーザーのクリック) の中で `chrome.permissions.request` を呼ぶ。拒否されたら、スイッチをオフに戻して理由を表示する
   - `permissions` と `host_permissions` (必須の権限) は増やさない。拡張機能の更新だけで、Chrome が権限の再承認を求めないようにする (`docs/PUBLISH.md` に書く)
   - 読み込みは、画像の取得だけ。X の非公開 API は呼ばない。自動スクロールもしない
3. 記憶装置の抽象化 (`src/shared/imagecache.ts`)。他のコードは `chrome.storage` / IndexedDB / ファイルを直接触らない
   - インターフェース: `put(tweetId, name, blob, meta)`, `get(tweetId, name)`, `removePost(tweetId)`, `usage()`, `list()`, `clear()`
   - 実装 2 つ
     - `idb`: 専用の IndexedDB (DB 名 `postshelf-images`)。キーは `tweetId/名前`。メタ (サイズ、保存日、ポスト ID) は別ストアに持つ
     - `dir`: File System Access API (`showDirectoryPicker`)。ディレクトリのハンドルは IndexedDB に保存する
   - テストでは、同じインターフェースのメモリ実装と、偽の `FileSystemDirectoryHandle` を使う
4. フォルダ保存 (`dir`) の構成 (ユーザー確認済み)
   ```
   選んだフォルダ/
   ├─ .postshelf        ← この拡張が作ったフォルダの目印 (中身は版番号だけ)
   ├─ README.txt        ← 「PostShelf の画像キャッシュです。消しても本体のデータは消えません」(利用者の言語で)
   └─ images/
      └─ <ポストID>/
         ├─ 1.jpg, 2.png ...   ← 拡張子はサーバーが返した形式に合わせる
         ├─ video-thumb.jpg    ← 動画のサムネイル (ある場合)
         └─ post.json          ← { tweetId, handle, displayName, url, savedAt (ISO 8601) }
   ```
   - フォルダ名とファイル名に、ハンドルは入れない (ポスト ID だけ)。投稿者の情報は `post.json` にだけ書く
   - `post.json` に本文は入れない
   - 1 枚につき 1 ファイル。画質を切り替えたときは、同じファイル名で上書きする
   - `.postshelf` があるフォルダにだけ書き込む。無いフォルダ (空でない) を選んだときは、確認ダイアログを出し、了承されたら `.postshelf` を作る。書き込みと削除は、`images/` の下の自分が作ったファイルだけ。選んだフォルダにある他のファイルには触らない
   - 「再スキャン」ボタン: フォルダの中を数え直し、拡張機能側のメタ (サイズ、ポスト ID) を作り直す。ポスト ID はフォルダ名から読む
   - アクセス許可が外れている (Chrome の再起動後など) ときは、設定画面に「許可が必要です」と「許可する」ボタンを出す。許可が無い間は書き込みを保留し、表示はキャッシュを使わずに X の URL へ切り替える
   - フォルダの選択は、タブ版の管理画面でだけ行う。サイドパネルで選べない (`showDirectoryPicker` が使えない) 場合は、「タブ版で選んでください」と案内する。拡張機能のページで `showDirectoryPicker` が使えるかは、実機で未確認なので、使えないときの代替表示を必ず入れる
5. キャッシュするタイミング
   - ポストを保存したとき (content script から background へ依頼し、background が画像を取得して保存する)
   - 「保存済みのポストの画像をまとめてキャッシュ」ボタン: 未キャッシュのポストの画像を 1 枚ずつ順に取得する。間隔を空ける (目安 300 ms)。進捗を表示し、いつでも中止できる。中断しても、次に押すと続きから
   - どちらも、オフのときは何もしない。失敗 (404 や通信エラー) は記録して、次の機会に再試行する。失敗が続く画像は、3 回で諦める
6. 容量の管理
   - 使用量は設定画面に「使用中 X / 上限 (画像 N 枚)」とバーで出す
   - 上限を超えるとき: `onFull: 'evict'` は、保存日が古いポストの画像から消す。`'stop'` は新しい画像を保存しない
   - 最大容量を下げたときは、確認ダイアログ (消える件数を表示) を出してから、すぐ整理する
   - ポストの削除、アカウントのデータ削除、「すべてのデータを削除」のときは、対応する画像も消す。キャッシュ側の削除に失敗 (フォルダの許可が無い、など) しても、ポストの削除自体は成功させ、後で整理が必要なことを表示する
7. 保存先の切り替え (`idb` ⇄ `dir`): 「移す / 移さない / キャンセル」を選ぶダイアログ。「移す」は進捗つき
8. 表示
   - カードのサムネイル、ビューアともに、キャッシュがあればキャッシュ (Blob から作った object URL。使い終わったら解放) を使う。無いときだけ X の URL を読む
   - キャッシュを使っていることが利用者に分かる表示は不要 (設定画面の使用量だけ)
9. エクスポート (JSON) に、画像は含めない (URL のみ)
10. 設定画面 (`src/manager/Settings.tsx`): `docs/mockups/media-viewer.html` の「設定: 画像のキャッシュ」のとおり。「データ」区画の近くに置く。説明文に次を入れる
    - 拡張機能を削除すると、ブラウザ内のキャッシュも消えること (選んだフォルダは消えない)
    - 本当に残したい画像は、「自分で選んだフォルダ」に保存すること
    - 保存データ本体の備えとして、JSON のエクスポートを使うこと
    - 初めてオンにするとき、Chrome が X の画像サーバーへのアクセス許可を求めること
11. 守ること
    - 画像は、この PC の中にだけ置く。外部のサーバーへ送らない
    - 取得先は `pbs.twimg.com` だけ (X が自分で読み込んでいる画像と同じ場所)
    - `README.md` のプライバシーの説明と `docs/PUBLISH.md` (権限の説明) に、キャッシュをオンにした場合の通信先と、optional な権限であることを書く
12. i18n: 設定画面の文言をすべて 8 言語で追加する
13. テスト
    - 記憶装置: メモリ実装とフォルダ実装 (偽のハンドル) の両方で、保存・取得・削除・使用量
    - フォルダ構成: パスの組み立て (`images/<ポストID>/N.ext`、`post.json` の中身)、`.postshelf` が無いフォルダへの書き込み拒否と確認、他のファイルに触らないこと
    - 容量: 古い順の整理、`onFull: 'stop'`、上限を下げたときの整理、取得失敗の再試行と 3 回での停止
    - 権限: 拒否されたらスイッチがオフに戻る
    - 設定の初期化とデータ削除にキャッシュが含まれる、ポスト削除でキャッシュも消える
    - まとめてキャッシュの中断と再開
