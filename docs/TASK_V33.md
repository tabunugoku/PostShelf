## A. 不自然な改行 (全画面)

### 原因
V28 から「日本語の折り返しは文節の区切りにする (`word-break: auto-phrase; line-break: strict`)」が画面の文字列のルールになっているが、**CSS に一度も入っていない** (`static/*.css` と `src/` に `auto-phrase` がない)。さらに、`manager.html` などに `lang` がなく、`:lang(ja)` も使えない。実機では「自動化さ / れたアクセス」のように、語の途中で折り返している。

### 直し方
1. 画面の言語を `document.documentElement.lang` に設定する。管理画面・サイドパネル (`manager.html` / `sidepanel.html`)、ポップアップ (`popup.html`) の起動時に、`chrome.i18n.getUILanguage()` の値を入れる (例: `ja`、`en-US`)。HTML の初期値は、`lang="ja"` のような固定にはしない。
2. 3 つの CSS (`static/manager.css`、`static/popup.css`、content script が挿入するスタイル) に、日本語の折り返しの規則を入れる。
   - `:lang(ja) body { word-break: auto-phrase; line-break: strict; }` (継承されるので、本文全体に効く)。ボタン・チップ・タブは `white-space: nowrap` のままにする。
   - 英語など他の言語は、通常の折り返し (規則を足さない)。
   - 長い文章 (設定の説明、案内、トースト、ポストの本文) に `text-wrap: pretty` を足し、1 文字だけの行を避ける。見出しとラベルには `text-wrap: balance`。
   - 既存の `overflow-wrap: anywhere` (本文の URL 用) は残す。
3. x.com のポップオーバー (`src/content/popover.ts` のスタイル) と、自動取り込みのパネル (`autocollectPanel.ts`) は、X のページの中にあり、`lang` が X の言語になる。ここでは、ポップオーバー / パネルのルート要素に `lang` 属性 (UI の言語) を付け、同じ規則をそのルートに適用する。
4. Chrome 119 未満では `auto-phrase` が無効 (通常の折り返し) になる。これは許容する。コメントに書く。

### 確認
- `:lang(ja)` の規則が 3 つの CSS (と content のスタイル) にある。`documentElement.lang` が起動時に設定される (jsdom のテスト)。
- 実機: 設定の長い説明 (全文取得、X のブックマークとの連動) で、語の途中で折り返さない。

## B. 管理画面のスクロール位置が、画面をまたいで残る

### 現象
ポスト一覧を下までスクロールしてから「設定」を開くと、設定の一番下 (「初期化と削除」) が出る。画面を切り替えても、同じスクロール位置が残っている。

### 直し方
- スクロールしているのは、画面全体 (またはメインの領域) で、ポスト一覧と設定が同じ要素を共有しているため。実際にスクロールしている要素を、まず特定する (`.main` か `document.scrollingElement`)。
- 規則:
  1. 設定を開いたとき: 先頭 (または、`#settings-...` のアンカーで開いたときは、その項目) へ移る。
  2. 設定から一覧へ戻ったとき: 設定へ移る前の、一覧のスクロール位置に戻す (戻せるときだけ。フォルダが変わっていたら先頭)。
  3. 別のフォルダ・スマートビューを選んだとき: 先頭へ移る。並べ替えや検索の変更でも、先頭へ移る。
  4. 保存データが変わっただけの再読み込み (自動取り込み中など) では、位置を動かさない。
- 一覧の位置は `useRef` に持つ (保存データには入れない)。`scroll-behavior` は `auto` (アニメーションしない)。
- サイドパネル版でも同じ。

### 確認
- 設定を開くと、設定の先頭が出る。戻ると、一覧が元の位置にある。フォルダを替えると先頭になる。保存の再読み込みで位置が飛ばない (テスト)。

## C. サイドパネルで、並べ替えのメニューが左にはみ出す

### 原因
`.listbox` が `right: 0; min-width: 100%` で、ボタンの右端に合わせて左へ広がる。サイドパネルでは、ボタンが左端にあり、メニューが画面の外へ出る。

### 直し方
- 並べ替えのメニュー (`SortMenu`、`static/manager.css` の `.listbox`) を、画面の中に収める。ボタンが左寄りのときは `left: 0`、右寄りのときは `right: 0`。開くときに、ボタンの位置 (`getBoundingClientRect`) と、メニューの幅から、はみ出さない側を選ぶ。どちらでも収まらないときは、画面の幅に合わせる (`max-width: calc(100vw - 16px)`)。
- 同じ原因の、他のメニュー (`.menu`、`.menu-left`、フォルダ選択など) も、サイドパネルの狭い幅 (320px 前後) で見切れないか確認する。見切れるものは同様に直す。
- 項目の文字は 1 行 (`white-space: nowrap`)。長いときは省略記号にする。

### 確認
- 幅 320px で、メニューの左右が画面内にある (jsdom では `getBoundingClientRect` をモックして、側の選び方をテストする)。

## D. x.com のポスト詳細で、フォルダのボタンの位置が合わない

### 現象
ポストの詳細ページ (`x.com/<user>/status/<id>`) で、操作の行 (返信・リポスト・いいね・ブックマーク・共有) の中で、フォルダのボタンが他のアイコンより少し上にあり、ブックマークの数字 (「785」) に詰まって見える。タイムラインでは正しい位置にある。

### 原因 (推測。実機の DOM は未確認)
`buttons.ts` の `createSeparateButton` が、ブックマークの要素の直後に `inline-flex` のボタンを挿入している。詳細ページの操作の行は、タイムラインとは違う構造 (数字つきのボタンが縦に並ぶ、`align-items` が `flex-start` など) で、挿入したボタンが他のアイコンと中心をそろえられていない可能性が高い。

### 直し方
1. まず、実機の DOM を確かめる前提で、次の手順を取る (クラウドの環境では x.com を開けないので、`test/fixtures/` に、詳細ページの操作の行の簡略 HTML を足す。構造は下の「想定」)。
2. ボタンに `align-self: center` を足す。
3. 左の余白 (`GAP`) だけに頼らず、ボタンが数字の列と重ならないように、ブックマークの要素と同じ親の中で、必要なら間隔を (4px → 8px まで) 足す。詳細ページとタイムラインで、同じ規則にする。
4. 親が `flex` でないとき (`display: flex` でない) は、ボタンの縦位置が変わらないことを確認するテストを足す。
5. 想定している詳細ページの構造 (fixture に使う。推測であることを、コメントに明記する): `div[role=group]` の中に、返信 / リポスト / いいね / ブックマーク / 共有が、横に並ぶ。ブックマークは `button[data-testid="bookmark"]` で、右に数字の `span` がある。親は `display:flex; align-items:flex-start`。

### 実機で確認してもらう項目 (必須。結果で、推測を直す)
- 詳細ページで、フォルダのボタンが、他のアイコンと同じ高さにある。ブックマークの数字と重ならない。
- ずれが残るときは、操作の行の HTML (開発者ツールで、`[role="group"]` を右クリック → Copy → Copy outerHTML) を共有してもらう。個人情報 (名前・本文) は消してから。
