# TASK v32: 自動取り込みの高速化 (待ちを適応式にする)

v31 が終わったあとに実施する。保存データの形は変えない。必須の権限は増やさない。外部通信もしない。

## 目的
自動取り込み (`src/content/autocollect.ts`) は、1 回のスクロールのあと、速度の設定に応じて **固定の時間** (ゆっくり 2〜4 秒、ふつう 1〜2.5 秒) 待ってから次へ進む。X の読み込みが速いときも待つので、無駄が大きい。

**新しいポストが DOM に出たら、短い待ちだけで次へ進む** ようにする。読み込みが遅いときは、いまと同じ時間まで待つ。つまり **最悪の場合の待ち時間と速度の設定の意味は変えず、速いときだけ速くなる**。

## 決まっている方針 (ユーザーの判断)
- 高速化は「待ちを適応式にする」だけを採用する。「速い」の速度設定の追加、スクロール量の増加、保存頻度の変更はしない。
- CLAUDE.md の自動スクロールの方針 (同意した取り込みだけ。速度を抑える。一時停止・停止ができる。X の制限を検知したら止める) を広げない。

## 仕様

### 待ちの決め方 (`loop` のスクロール後)
いまの `await this.d.sleep(this.delay())` を、次の待ちに置き換える。

1. `ceiling` = いまの `delay()` の値 (速度の範囲から乱数で決める。変えない)。
2. `floor` = 速度ごとの最小の待ち。ゆっくり 800ms、ふつう 400ms。実際の下限は `floor` から `floor × 1.5` の乱数 (機械的な一定間隔にしない)。いずれも `ceiling` を超えない (`min(…, ceiling)`)。
3. まず下限まで待つ。そのあと 100ms ごとに「まだ見ていない新しいポストが DOM にあるか」を調べ、**あれば直ちに待ちを終える**。なければ `ceiling` まで続け、それでも出なければ終える (いまと同じ)。
4. 待ちを終えたあとの処理 (読み込み中の表示が消えるまで最大 8 秒待つ処理、`moved` の判定、停止の判定) は変えない。新しいポストが出ても、「読み込み中」の表示が残っているあいだは、いまどおり待つ。
5. 待っているあいだも、停止・一時停止 (`alive()` の確認) に反応する。1 回の `sleep` を長くせず、100ms 刻みで確認する。

### 新しいポストの検出 (`CollectDeps`)
- `hasUnseen(seen: ReadonlySet<string>): boolean` を `CollectDeps` に足す。画面の `article` から、ポストの ID だけを軽く読み、`seen` にないものがあれば true。**`collectVisible()` を 100ms ごとに呼ばない** (スナップショットの抽出は重い)。ID の取り出しは、既存の `collect.ts` / `selectors.ts` の方法を使い、セレクタを増やす場合は `src/shared/selectors.ts` に足す。
- 既定の実装は `defaultDeps()` に置く。テストでは差し替える。

### 変えないもの
- `SPEED_RANGES` の値と意味 (待ちの上限)、`SCROLL_RATIO`、`END_STREAK`、`STALL_END`、`FLUSH_EVERY`、`LOAD_WAIT_MS`。
- 終了の判定 (新しいポストが出ない回数)。新しいポストが出ない場合は、いまと同じ時間 (`ceiling`) だけ待つので、判定の回数と時間は変わらない。
- 件数の上限、時間の上限、制限の検知、隠れたタブ・アカウント切替での停止、保存、全文取得。
- 確認画面の説明、設定の文言。速度の選択肢は増やさない。新しい文言は足さない。

## 守ること
- 保存データの形は変えない。必須の権限は増やさない。外部通信はしない。
- 下限を設けて乱数を入れる。待ちを 0 にしない。
- 実機で確認できない前提 (X が新しいポストをいつ DOM に出すか) は、コメントに「実機未確認」と書く。
- スクリーンショットは撮らない・足さない。

## テスト (`test/autocollect.test.ts`)
- 新しいポストが下限の直後に出るとき、待ちが `floor` 付近で終わる (`ceiling` より明らかに短い)。
- 新しいポストが出ないとき、待ちが `ceiling` まで続く (いまと同じ)。終了判定 (`END_STREAK`、`STALL_END`) の挙動は変わらない。
- 待っている最中に `pause` / `stop` を呼ぶと、100ms 以内に反応する。
- 下限が `ceiling` を超えない (`ceiling` が小さい場合)。
- `isLoading()` が true のあいだは、新しいポストが出ていても、次へ進まない。
- 既存のテスト (`SPEED_RANGES` の値のテストを含む) が、そのまま通る。

## 実機で確認する項目 (`docs/MANUAL_TEST.md` に v32 の節を足す)
- 100 件ほどの自動取り込みで、v1.1.1 と比べて所要時間が短くなる (目安: ふつうで 2〜3 割短い)。
- 取り込み中に X の制限の表示が出ない。出たら、速すぎるので `floor` を上げる (結果を報告する)。
- 一覧の最後まで進んで、終了の判定が従来どおり出る。
- 一時停止・停止が、押してすぐ効く。
- 取りこぼし (読み飛ばし) がない: 取り込んだ件数が、v1.1.1 と同じ範囲で一致する。
