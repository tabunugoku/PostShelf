# よくある質問 (FAQ)

## PostShelf のデータはどこに保存されますか？
PostShelf は **デスクトップ版 Chrome の拡張機能** で、データ (フォルダ・保存したポスト) はその端末のブラウザ内 (`chrome.storage.local`) にだけ保存されます。外部サーバーには一切送信しません。

## スマホの X アプリでブックマークしたポストは PostShelf に入りますか？
**自動では入りません。**
- X のスマホアプリでブックマークしたものは、X のサーバー側に保存されるだけです。
- 拡張機能はスマホのアプリには入れられないため、PostShelf はスマホでの操作を知ることができません。

## スマホでブックマークした分を PostShelf に入れるには？
デスクトップの Chrome で取り込みます。

1. PostShelf を入れた Chrome で x.com にログインし、左メニューの「履歴」を開いて「ブックマーク」タブを選ぶ (`https://x.com/i/history`。X の表示名が変わっても、このアドレスを直接開けば同じ画面です。「いいね」タブ (`/i/history/likes`) では取り込みボタンは出ません)
2. 取り込みたいポストが画面に出るまで、自分でスクロールする (全部を自動で取り込みたいときは、下の「ブックマークを自動で取り込めますか？」を見てください)
3. 画面右下の取り込みボタン (「未取り込み N 件」。「いま見えている分だけ取り込む」ボタンです) を押す
4. 取り込まれたポストは「未分類」フォルダに入ります。manager で整理してください (すでに取り込み済みのポストは重複しません)

ボタンの表示:
- **未取り込み N 件**: 画面に出ているポストのうち、PostShelf にまだ保存されていない件数
- **すべて取り込み済み**: 画面に出ているポストはすべて保存済み

※ PostShelf が読むのは、表示中の画面の DOM だけです。X の非公開 API は使いません。

## ブックマークを自動で取り込めますか？ (v15)
**はい。ただし、あなたが確認の画面で同意して「始める」を押したときだけ動きます。**
- x.com の「履歴」→「ブックマーク」(`/i/history`) のタブを、PostShelf があなたの代わりに少しずつスクロールし、画面に出たポストを読んで取り込みます (「いいね」タブなど、ほかのページでは動きません)
- X の非公開 API や GraphQL は呼びません。外部への送信もありません。画面に出ているポストの DOM を読むだけです
- インストールした直後、アカウントを切り替えた直後、ページを開いただけでは、**自動では始まりません**。初めて使うアカウントには「X のブックマークを取り込みますか？」という案内が出るだけです
- 始めるには、案内の「取り込みを始める…」、設定の「データ」にある「ブックマークを自動で取り込む…」、x.com の画面右下の「自動で取り込む…」のどれかから、確認の画面を開きます。速度と 1 回の上限を選び、注意を読んで同意のチェックを入れると、「取り込みを始める」が押せます
- 使いたくないときは、設定の「自動取り込みを使う」をオフにします。案内も開始のボタンも出なくなります
- 始めると、x.com のブックマークのタブが開き (すでにあればそれが前面に出ます)、3 秒後に始まります。この間は「キャンセル」できます

### 規約上のリスクについて
- 自動スクロールは、X の規約が禁じる「自動化されたアクセス」とみなされる可能性があります。PostShelf は、速度を抑え、いつでも止められ、X が制限やエラーを出したら止まるようにしていますが、**それで安全になるわけではありません**
- アカウントの制限や凍結などが起きても、PostShelf の作者は責任を負えません。取り込みは、あなた自身の判断で、あなた自身のアカウントに対してだけ行ってください
- 不安なときは、自動取り込みを使わず、自分でスクロールして「いま見えている分だけ取り込む」を使ってください (上の「スマホでブックマークした分を PostShelf に入れるには？」)
- この判断の根拠にした、類似拡張機能の比較と X の規約の整理は、リポジトリに含めていません。要点は上のとおりです

### 速度と 1 回の上限
- **速度**: 「ゆっくり」(おすすめ。スクロールのたびに 2〜4 秒待つ) と「標準」(1〜2.5 秒待つ)。画面の高さの約 8 割ずつスクロールします。1 分あたりの件数は目安で、X の読み込みの速さで変わります
- **1 回の上限**: 「300 件ごとに一度止める」(おすすめ) / 「100 件ごと」/「止めない」。上限に達すると一時停止します。続けるときは「再開」を押してください (もう一度、同じ件数ぶん進みます)

### 一時停止と再開
- いつでも「一時停止」と「停止」を押せます。x.com の画面右下のパネルと、管理画面の上部の表示のどちらからでも操作できます。止めても、そこまでの分は保存されています
- 次の場合は、自動で一時停止します: 別のタブに切り替えたとき / アカウントが変わったとき / X がエラーや制限を表示したとき / 上限に達したとき / ブックマークの画面から移動したとき
- **再開は、あなたが「再開」を押したときだけです。** 自動では再開しません。X の制限を検知して止まったときは、パネルに「15 分以上あけてから再開してください」と出ます。「15 分後に再開する」を押すと再開を予約できますが、これも押したときだけです (予約中もこのタブを開いたままにしてください)
- ページを再読み込みしたあとの再開では、一覧の先頭からもう一度スクロールします。**取り込み済みのポストは読み飛ばします** (読み飛ばす間も、同じ速度を守ります)
- 終わりの判定は、新しいポストが 5 回続けて出なかったとき (読み込み中の表示が出ていないとき) です。**実機で確認できていない**ので、うまく終わらないときは「ここで終了」を押してください

### 並び順 (x.com と同じ順に並びます)
x.com のブックマークは、新しく追加した順で、下へスクロールするほど古くなります。取り込んだ時刻をそのまま「保存した日時」にすると、順番が逆になってしまうので、PostShelf は **一覧での位置から「保存した日時」を決めます**。
- 初回は、いちばん上のポストをいちばん新しく、下のポストほど少しずつ古い日時にします。「保存が新しい順」で、x.com と同じ並びになります
- すでに取り込み済みのポストは変えません。途中で止めて再開しても、新しく見つかったポストは、x.com の並びで直前にあったポストのすぐ後ろに入ります
- 途中で X 側にブックマークが増えたときは、一覧の先頭に出てくるので、取り込み済みより上に入ります
- PostShelf のボタンで保存した日時が、x.com の並びと食い違っていても、データは失いません (並びが少しずれることがあります)
- 「いま見えている分だけ取り込む」(手動) も、同じ並び順の処理を使い、取り込み済みのポストはスキップします。なお、一覧の途中まで下がった状態で押すと、見えている分は、取り込み済みより上に入ります
- すでに取り込んだデータの「保存した日時」は、書き換えません (移行はしません)

## 長いポストの全文は取れますか？ (v24)
**はい。保存した時点で、X が「さらに表示」とたたんでいたポストだけ、全文を取りに行きます。**
- タイムラインのたたまれたポストには、全文が画面に無いので、そのポストのページを、**裏のタブで開いて読み、閉じます**。タイムラインの「さらに表示」は押さず、いま見ているタブは移動も操作もしません。自動のスクロールもしません
- 同時に開く裏のタブは 1 つで、次を開くまで 4〜8 秒あけます。X が制限や警告を出したと思われるとき、続けて 3 件取れなかったときは止まり、設定にその理由が出ます
- 自動取り込みで取り込んだ分は、終わってから、最大 30 件だけ取りに行きます。残りは、設定の「全文を取得していないポスト: N 件」と「いま取得する」(最大 50 件。確認の画面が出ます) で、必要なときだけ取れます
- 自分でポストの個別ページを開いたときも、保存済みのたたまれたポストは、全文に更新されます
- 取れなかったポストには、「全文は X で見る」のリンクが出ます
- 使いたくないときは、設定の「長いポストの全文を取得する」をオフにします。たたまれた分だけを保存します

### 規約上のリスクについて
- ポストのページを裏のタブで開く動作は、X の規約が禁じる「自動化されたアクセス」とみなされる可能性があります。間隔や上限を設けていますが、**それで安全になるわけではありません**。法的な助言ではありません
- アカウントの制限などが起きても、PostShelf の作者は責任を負えません。不安なときは、設定でオフにしてください
- PostShelf 自身は、外部への送信をしません (X のページをブラウザが開くだけです)

## フォルダを作らなくても保存できますか？ (v15)
**はい。「未分類」に保存できます。** x.com のフォルダボタンを押したときのポップオーバー、管理画面の「フォルダを変更」、サイドパネルの「いま開いているポストを保存」のどれにも、先頭に「未分類」の行があります。フォルダが 1 つもなくても、「未分類」にチェックを入れるだけで保存されます。
- 「未分類」は、ほかのフォルダと同時には選べません。フォルダを選ぶと「未分類」が外れ、「未分類」を選ぶとほかのフォルダが外れます
- 保存済みのポストで、最後に残ったフォルダのチェックを外すと、保存が消えるのではなく「未分類」に戻ります
- PostShelf から外す (保存を消す) には、ポップオーバーの「PostShelf から外す」を使います。管理画面では、ポストの「削除」です。X 側のブックマークは、連動モードがオンのときだけ、いっしょに外れます

## X のブックマークが多すぎて古いものが取り込めません
X のブックマーク一覧には、表示件数の上限があるとされています。800〜1000 件程度と言われていますが、公式には確認できていません。上限を超えて見えなくなった分は、画面に出てこないため取り込めません。**日常的にこまめに取り込む**ことをおすすめします。

## 別のパソコンと同期できますか？
**自動の同期はありません。** 手動で移行できます。

1. 元の端末で manager を開き、左下の「エクスポート」で JSON ファイルを保存
2. 移行先の Chrome (PostShelf 入り) で manager を開き、「インポート」でその JSON を選ぶ
3. 同じ ID のフォルダ・ポストは上書き、それ以外は追加 (マージ) されます

エクスポートの形式は言語に依存しません。

## 今後の課題: クラウド同期
複数端末での自動同期 (クラウド同期) は、PostShelf の「データは端末内のみ」「外部通信なし」という方針と衝突するため、**現時点では対象外**です。実現するなら、ユーザーが明示的に有効にするオプトイン方式や、`chrome.storage.sync` (Chrome アカウント経由、容量制限が小さい)、ユーザー自身のストレージを使う方式など、プライバシー方針との両立を含めて別途検討が必要です。

## サイドパネルで開けますか？
Chrome 114 以降で、popup の「サイドパネルで開く」から開けます。設定で、ツールバーアイコンのクリック時の動作 (ポップアップ / サイドパネル) を切り替えられます。

## 複数の X アカウントを使っています。ブックマークは混ざりませんか？
混ざりません。PostShelf は、x.com の画面に出ているアカウント (左メニュー下部の表示) を読み取り、**保存するときのアカウントごとにフォルダとポストを分けて**います。同じポストを別のアカウントで保存すると、別々に保存されます。

- manager (タブ / サイドパネル) の左上のアカウント切替で、見るアカウントを選べます。ここで切り替えても、**X のログイン状態は変わりません** (拡張から X のアカウントは切り替えられません)
- 既定は、x.com で最後に使っていたアカウントです。x.com でアカウントを切り替えると、manager も追従します
- アカウントを読み取れないとき (x.com の画面が変わった、など) は、保存と取り込みはできません。理由が画面に出ます

## X のハンドル (@名前) を変えました。保存したデータはどうなりますか？
PostShelf はハンドルでアカウントを区別するため、ハンドルを変えると**別のアカウント**として扱います。古いハンドルで保存したデータは、そのまま古いハンドルの棚に残ります。

新しいハンドルへ移すには、manager のアカウント切替を開き、古いアカウントの行の「割り当て…」から、移動先に新しいアカウントを選びます。同じポストがすでに移動先にある場合は、そのポストが入っているフォルダを合わせます。

## 「アカウント未設定」とは何ですか？
アカウントごとに分ける機能を入れる前に保存したデータと、アカウントを判定できなかったときに保存したデータを入れる棚です。データがあるときだけ、アカウント切替に出ます。

x.com でログインした状態で manager を開くと案内が出ます。「割り当て…」から、どのアカウントのデータかを選ぶと、そのアカウントへ移せます。

## 設定を初期の値に戻したい / すべてのデータを消したい
設定画面の下の方にあります。

- **設定を初期の値に戻す**: 連動モード、標準ボタンの動作、開き方、表示形式などの設定だけを戻します。フォルダ、保存したポスト、アカウント情報は消えません。押した直後に、5 秒間「元に戻す」が出ます
- **すべてのデータを削除**: フォルダ、保存したポスト、アカウント情報を消します (設定は残ります)。確認の画面で件数が出ます。先に「JSON を書き出す」でバックアップできます。「削除」と入力しないと実行できません。**取り消しはできません**

## 画像を大きく見るには？
manager (タブ / サイドパネル) のポストで、画像を押すと全面表示になります。

- 複数枚あるときは、左右の「‹ ›」か、キーボードの `←` `→` で前後に移れます。`Esc`、右上の「✕」、背景を押すと閉じます
- 「元のサイズで開く」は、画像だけを新しいタブで開きます。「X でポストを開く」で元のポストへ移れます
- 画像が読み込めないとき (元のポストが削除された、X 側で画像の場所が変わった、など) は、その理由と、「保存してある小さい画像を表示」が出ます

## 動画は PostShelf で再生できますか？
できません。動画の再生用のファイルは、X の画面から正規の方法で取り出せないためです (X の非公開 API は使わない方針です)。PostShelf が保存できるのはサムネイルだけです。動画のサムネイルを押すと、「X で動画を再生」でポストが新しいタブで開きます。

サムネイルは、新しく保存したポストから残ります。以前に保存した動画つきのポストは、サムネイルがなく、動画のアイコンの枠で表示されます。

## 動画のポストと、画像のポストの見分け方は？ (v20)
動画のポストには「動画」の札 (サムネイルの中央に再生ボタン、左下に「動画」。リスト表示では行の右端) が付きます。画像が 2 枚以上のポストには、枚数の札が付きます。画像が 1 枚のポストには、何も付きません。

- X の GIF は、動画と区別できないので、「動画」の札が付きます
- v7 より前に保存したポストは、動画かどうかを保存していないので、札が付きません (動画のポストでも、画像のポストと同じ見た目になります)。絞り込みの「画像あり」にも、同じように残ります
- 動画の長さは保存していないので、札には出ません

## 画像のキャッシュとは？ (設定 → 画像のキャッシュ)
保存したポストの画像を、PostShelf 側にも残す機能です。**初期値はオフ**です。X 側でポストが削除されても、残した画像は見られます。動画はサムネイルだけです。

- **オンにするとき:** Chrome が「pbs.twimg.com (X の画像サーバー) へのアクセス」の許可を求めます。許可しないとオンにできません。この許可は、機能をオンにしたときだけ求めます (拡張機能の更新では求められません)
- **保存先:** 「ブラウザの中」(おすすめ) か、「自分で選んだフォルダ」を選べます。最大容量 (500 MB 〜 10 GB、または指定)、画質 (標準 / 元のサイズ)、いっぱいになったときの動作 (古いものから消す / 新しい画像を保存しない) も選べます
- **画像の取得:** ポストを保存したときと、「保存済みのポストの画像をまとめてキャッシュ」を押したときです。まとめてキャッシュは、1 枚ずつ順に取得し、進捗を表示します。いつでも中止でき、次に押すと続きから始まります。取得に失敗した画像は、次の機会に再試行します。3 回失敗すると、再試行を止めます
- **削除:** ポストを削除すると、そのポストの画像も消えます。キャッシュ側の削除に失敗したときも、ポストの削除は成功します。設定画面に「整理が必要」と出るので、あとで「今すぐ整理」を押してください
- **通信先:** 画像の取得先は `pbs.twimg.com` だけです (X が自分で読み込んでいる画像と同じ場所)。取得した画像は、この PC の中にだけ置き、外部のサーバーへは送りません。JSON のエクスポートには、画像は入りません (URL のみ)

## キャッシュした画像はどこに保存され、いつ消えますか？
**ブラウザの中** (拡張機能のデータ領域) に保存した場合、次のとき消えます。

- 拡張機能を削除したとき
- Chrome のプロファイルを削除したとき

Chrome の「閲覧履歴データの削除」では、標準の画面操作では消えない見込みです。ただし、これは Chrome の仕様に基づく説明で、実機で確かめるまでは断定できません (確認項目は `docs/MANUAL_TEST.md` にあります)。

本当に残したい画像は、**「自分で選んだフォルダ」に保存**してください。拡張機能を削除しても、選んだフォルダは消えません。また、保存データ本体 (フォルダとポストの情報) の備えには、JSON のエクスポートを使ってください。

## 「自分で選んだフォルダ」には何が作られますか？
選んだフォルダの中に、次のものを作ります。

```
選んだフォルダ/
├─ .postshelf        PostShelf が作ったフォルダの目印 (版番号だけ)
├─ README.txt        「PostShelf の画像キャッシュです。消しても本体のデータは消えません」
└─ images/
   └─ <ポストID>/
      ├─ 1.jpg, 2.png ...   画像 (拡張子は X が返した形式)
      ├─ video-thumb.jpg    動画のサムネイル (ある場合)
      └─ post.json          { tweetId, handle, displayName, url, savedAt }
```

- フォルダ名とファイル名には、ポスト ID だけを使います (投稿者のハンドルは入れません)。投稿者の情報は `post.json` にだけ書きます。`post.json` に**ポストの本文は入りません**
- 書き込みと削除は、`images/` の下の PostShelf が作ったファイルだけです。選んだフォルダにある他のファイルには触りません
- すでに別のファイルが入っているフォルダを選ぶと、確認が出ます。了承すると、`.postshelf` と `README.txt` と `images/` を作ります
- フォルダの選択は、タブ版の管理画面で行います (サイドパネルでは選べません)
- 設定の「再スキャン」で、フォルダの中を数え直せます (フォルダ名のポスト ID から、サイズなどを作り直します)

## フォルダへのアクセス許可が外れました
Chrome を再起動すると、選んだフォルダへのアクセス許可が外れることがあります。設定の「画像のキャッシュ」に「許可が必要です」と「許可する」ボタンが出るので、押して許可してください。許可するまでは、画像はフォルダに書き込まれず、X の画像サーバーから読み込まれます。許可すると、書き込みが再開します。
