# 追加タスク (v14): 日本語表現の修正 (手順書 `docs/INSTALL.md`)

前提: v13 まで `claude/serene-johnson-j5tpe7` で実装済み。続きで作業する (最初に `origin/main` をマージ)。v12 と同じ進め方。ロジックは変えない。文言とドキュメントだけを直す。

## A. `docs/INSTALL.md` (日本語)
1. 「5. うまくいかないとき」の最後の項目
   - 修正前: 「画面の表示が、X の仕様変更で壊れたとき: 設定の「X の画面構造」から、診断情報をコピーして報告できます。」
   - 修正後: 「X の仕様変更で画面の表示がおかしくなったとき: 設定の「X の画面構造」から、診断情報をコピーして報告できます。」
   - 理由: 「壊れた」は、データや画面の状態に使うと意味が広すぎる。「おかしくなった」にする
2. 「2. 更新するとき」の「やってはいけないこと:」
   - 修正後: 「やってはいけないことは次の 2 つです。」(続く 2 項目の箇条書きはそのまま)
   - 理由: 文末のコロンで箇条書きを導くのをやめ、文にする
3. 「1. はじめて入れるとき」の手順 2
   - 修正前: 「**この場所を、今後ずっと使います**。」
   - 修正後: 「**この場所を今後ずっと使います**。」(太字は残す)
   - 理由: 短い句の途中の読点は、読み分けの役割がないので外す

## B. 他のファイルへの反映
1. `docs/INSTALL.en.md`: 1 と 2 と 3 に当たる箇所の意味が、日本語と同じであることを確認する (「壊れた」に当たる語が、画面の表示の不具合を指す自然な表現になっているか。例: "the display looks wrong")。違えば直す
2. `docs/PUBLISH.md`、`README.md`、`docs/FAQ.md` に、同じ言い回し (「壊れた」を画面やデータに使っている箇所、「…こと:」で終わる箇所) があれば、同様に直す。画面の文言 (`_locales`) は、今回は対象外
3. 他言語の `messages.json` は、今回は変更しない
