## D. 左メニューの選択中の見た目 (ダークモード)
実機のダークモードで、選択中のフォルダ行 (例: 「すべて」) の左端に、薄いグレーの縦線が角丸で欠けたように出ている。モックアップ (`docs/mockups/proposal-v6.html`) には無い表現で、ユーザーは気に入っていない。
1. `static/manager.css` の `.fr.on` から左端の縦線 (`box-shadow:inset 3px 0 0 var(--text-primary)`) を外す。選択中の表現は、背景色 (`--fill-ghost-selected`) と太字だけにする (モックアップの `.fr.on` と同じ)
2. 同じ縦線・下線の `box-shadow:inset` を使っている他の場所 (`.seg button.on` の下線、`.post.selected` などの左線) も、モックアップと見比べる。モックアップに無い装飾は外す。ただし、色だけに頼らず選択状態が分かること (v4-C の基準) は守る。外す代わりに、太字・背景の濃さ・`aria-current` / `aria-selected` で区別する
3. 選択中の背景は、ダーク/ライトの両方で、非選択の行 (hover 時を含む) と区別できる濃さにする (v7-A のコントラストテストの対象に加える)
4. タブ版とサイドパネル版の両方に反映する。更新したスクリーンショットを `docs/screenshots/` に保存する

## E. X のアカウント切り替えへの対応
現状は、どの X アカウントで保存したかを記録していない。アカウントを切り替えると、別のアカウントのブックマークが同じ棚に混ざる。
方針 (ユーザーの要望): 「保存したアカウントが分かる」「拡張機能の中でアカウントを切り替えて見られる」。

1. アカウントの判定 (content script)
   - ユーザーが見ている x.com の画面から、現在ログイン中のアカウントの `@ハンドル` と表示名を DOM で読む。X の非公開 API は呼ばない。識別には左メニュー下部のアカウント切替ボタン (`data-testid="SideNav_AccountSwitcher_Button"` の想定。実機では下部に表示名と `@tabunugoku_dev` が出ている) を使う
   - セレクタは `src/shared/selectors.ts` に候補リストで集約する (v7-D の `queryFirst` を使う)。読めない場合は null を返し、例外にしない
   - ハンドルは小文字に正規化して ID とする。ハンドルは変更できるため、変更すると別アカウント扱いになる。この限界を FAQ に書き、データを別アカウントへ付け替える手段 (下記 E-2 の「割り当て」) を案内する
   - 現在のアカウントは、content script が読み取るたびに `chrome.storage.local` の別キー (例: `lastSeenAccount`) に保存する。manager、サイドパネル、popup はそれを読んで既定の表示アカウントにする
2. データモデル
   - `Account { id: string (正規化したハンドル); handle: string; displayName?: string; avatar?: string; lastSeenAt: number }` を追加
   - `Folder` と `Bookmark` に `accountId` を持たせる。フォルダ・ブックマークはアカウントごとに分ける (別アカウントのフォルダは見えない)。同じポストを別アカウントで保存した場合は、別々のブックマークとして扱う (キーは `accountId + tweetId`)
   - 既存データの移行: スキーマバージョンを上げ、`accountId` が無い既存のフォルダ・ブックマークは、特別なアカウント `unknown` (表示名は「アカウント未設定」) にまとめる。移行は 1 回だけ、冪等、データを失わないこと。移行結果をメモリ上で検証し、失敗時は何も書き込まない
   - 「アカウント未設定」のデータは、ユーザーが操作して特定のアカウントへ移せる (「このアカウントに割り当てる」。同じ tweetId が移動先にすでにある場合は統合する)。同じ操作で、ハンドル変更後の付け替えもできる。以降、新規保存で `unknown` になるのは、アカウントを判定できなかったときだけ
   - JSON のエクスポート/インポートもアカウント対応にする (エクスポートのバージョンを上げる。旧形式のインポートは `unknown` に入れる。旧形式の読み込みテストを残す)
   - `src/shared/storage.ts` に集約する。他のコードは `chrome.storage` を直接触らない (既存ルール)
3. x.com 上の動作 (content script)
   - ポップオーバーの上部に「保存先: @ハンドル」を表示する (アバター小。判定できないときは警告の文言 `accountUnknown`)
   - 保存は、判定できた現在のアカウントに対してだけ行う。ポップオーバーを開いている間にアカウントが切り替わったら、閉じて開き直す
   - 連動モード (X 標準のブックマークも付ける) のときの標準ボタン操作は、これまでどおり。アカウントとは無関係
4. manager (タブ/サイドパネル共通)
   - 左サイドバーの最上部に「アカウント切替」(現在表示中のアカウントのアバター + `@ハンドル` + ▾)。押すと、保存履歴のあるアカウント一覧 (各アカウントの保存件数つき) と「アカウント未設定」(データがあるときだけ) が出る。キーボードで操作でき、フォーカスが見える
   - 既定の表示アカウントは `lastSeenAccount`。ユーザーが手動で選んだアカウントは設定に記憶し、次回もそれを使う。ただし x.com で別のアカウントに切り替えて保存したときは、新しいアカウントの表示に切り替わり、そのことが分かる短いトースト (「@xxx に切り替えました」) を出す
   - 管理画面のアカウントを切り替えても、X 側のログイン状態は変わらない (拡張から X のアカウントを切り替える操作はできない)。画面上でそう分かる一言を添える
   - 件数、フォルダ一覧、検索、スマートビュー、取り込みバナーは、表示中のアカウントの分だけを対象にする
   - アカウント一覧の各行に「このアカウントのデータを削除」(アプリ内の確認 UI。件数を表示。取り消しはできないことを明記) を置く
5. 取り込み (`/i/history`)
   - 取り込みは、現在ログイン中のアカウントとして記録する。アカウントを判定できなければ取り込みボタンを無効にし、理由を表示する
   - 取り込みバナーの未取り込み件数も、アカウントごとに数える
6. popup: 件数は現在のアカウントのもの。アカウント名を表示する
7. i18n: 追加する文言は 8 言語すべて。ja は v8 の方針 (全角括弧、「自分で」「スマホ」) に従う
8. テスト (vitest + jsdom)
   - アカウントの判定 (複数の候補セレクタ、判定不能で null、ハンドルの正規化)
   - 保存が現在のアカウントに紐づく。別アカウントのデータは混ざらない。同じ tweetId を別アカウントで保存できる
   - 旧データの移行 (冪等、失敗時に書き込まない、`unknown` への割り当てと統合)
   - エクスポート/インポート (新形式、旧形式)
   - manager のアカウント切替 (一覧、件数、切替で表示が変わる、`unknown` の表示条件)
   - 判定不能時に保存・取り込みが無効になる
9. `docs/MANUAL_TEST.md` に追加: アカウントを 2 つ使い、それぞれで保存して混ざらないこと、x.com でアカウントを切り替えて保存したときの manager の追従、既存データの移行後の「アカウント未設定」の扱い
10. `docs/FAQ.md` に追加: アカウントごとにデータが分かれること、ハンドル変更時の扱い、「割り当て」での付け替え

## G. タブ版 manager のレイアウト (左メニューを画面の左端へ)
実機のタブ版では、画面全体が `max-width:1200px` で中央寄せになり、広い画面では左メニューが画面の左端から離れて、左右に大きな余白ができる。ユーザーの要望は「左メニューは画面の左端に寄せる。管理画面全体の横幅を固定する必要はない」。
1. `static/manager.css` の `.layout-wide` (`max-width:1200px;margin:0 auto`) から横幅の上限と中央寄せを外す。左メニュー (240px 固定) は画面の左端に付け、右のメインが残りの幅をすべて使う
2. メインの内部
   - ツールバー (検索、並べ替え、表示切替、絞り込みチップ) とリスト表示、グリッド表示は、メインの幅いっぱいに広げる
   - ポスト表示 (X 風カード) は、横に長すぎると読みづらいので、カードの列に上限幅 (目安 720px) をつけ、メインの左に寄せる。中央寄せにしない。上限幅は CSS 変数 1 つで調整できるようにする
   - グリッド表示は、幅に応じて列数が増える (現在は 3 列固定なので `repeat(auto-fill,minmax(…))` などにする。最小の列幅を決め、狭いときは v7 の既存のレスポンシブを壊さない)
3. サイドパネル版 (`.layout-narrow`) と、狭い幅 (幅 900px 未満など v7 で決めたブレークポイント) の挙動は変えない
4. 確認する幅: 1280px、1920px、2560px、900px 前後。各幅でスクリーンショットを撮り、`docs/screenshots/` に保存する (ライト/ダーク)
5. テスト: CSS のため jsdom では見た目を検証できない。`.layout-wide` に `max-width` と `margin:0 auto` が残っていないことを、CSS を読む簡単なテストで固定する
6. `docs/MANUAL_TEST.md` に追加: 広い画面 (1920px 以上) で、左メニューが画面の左端に付いていること、ポスト表示の列が読みやすい幅で左に寄っていること
