# TASK v36: 「すべて」の段階表示が止まる原因の修正、「すべて表示」の固まり、詳細ページの丸の大きさ

v35 の開発版を実機 (保存 5,056 件) で確認した結果の修正。保存データの形は変えない。必須の権限は増やさない。外部通信もしない。新しい文言は足さない。

## A. 「すべて」で 30 件を超えて読み込まれない (原因を特定済み)

### 原因 (ブラウザで再現し、確かめた)
v35 の `dist` を、擬似の `chrome.*` と 5,056 件のデータでブラウザに読み込ませて再現した。段階表示の `useEffect` (`src/manager/App.tsx` の `sentinelRef` を使う効果) の実行の記録は次のとおりだった。

```
{ el: false, remaining: 0,    rc: 30 }   ← データを読む前
{ el: false, remaining: 5026, rc: 30 }   ← データを読んだあと。それでも el (センチネル) が null
```

効果は `[renderCount, remaining, resetKey]` が変わったときにしか再実行されない。データを読んだあとの描画では、**センチネルの DOM がまだ作られていない (`sentinelRef.current` が null)** ため、`if (!el || remaining <= 0) return` で何もしない。そのあと、センチネルが DOM に出ても (別の状態の変更で一覧が描かれるため)、上の 3 つの値は変わらないので、効果は再実行されず、`scroll` の監視も `IntersectionObserver` も付かない。`growTo` は一度も呼ばれない (記録で確認)。

起動直後に開く「すべて」(最後に開いたフォルダ) だけで起きるのは、そのとき一度も `resetKey` が変わらないから。「未分類」などへ移ると `resetKey` が変わって効果が再実行され、センチネルがあるので、増えるようになる。そのあと「すべて」に戻っても、増える (報告と一致)。

### 直し方
- `sentinelRef` (`useRef`) をやめ、**コールバック ref + 状態**にする: `const [sentinel, setSentinel] = useState<HTMLSpanElement | null>(null);` を作り、`<span ref={setSentinel} …>` とする。効果は `const el = sentinel;` を使い、依存に `sentinel` を足す: `[sentinel, renderCount, remaining, resetKey]`。センチネルが DOM に出入りしたときに、効果が再実行される。
- v35 で足した `scroll` / `resize` の監視と `IntersectionObserver` は、そのまま残す (どちらでも増やせる、冗長な安全策)。ただし、効果が再実行されるたびに付け外しするので、リスナーのリークがないことを確かめる。
- 同じ型の問題 (DOM の要素を `useRef` に入れて、効果の中で `ref.current` を読み、要素が遅れて現れる) が、ほかにないか、`src/manager/` と `src/popup/` の `useEffect` / `useLayoutEffect` を点検する。見つかったものは、同様に直し、報告に書く。

### テスト (jsdom)
- 上の記録を再現する: 最初の描画でデータが空 (一覧が描かれない) → 次の描画でデータが入り、`remaining > 0` で、センチネルが初めて DOM に出る。このとき、`renderCount` / `remaining` / `resetKey` が変わらなくても、効果が再実行され、センチネルが交差 (または `scroll`) したときに `renderCount` が増える。
- 修正前のコードでは、このテストが失敗する (最初に確かめる)。

## B. 「すべて表示」で画面が固まる

### 現象
「すべて表示」を押すと、5,056 件を一度に描くので、管理画面が固まる (実機。画像つきのポストが多いため、特に重い)。

### 直し方
- 「すべて表示」を、**少しずつ増やす**ようにする。押すと、`renderCount` を、`requestAnimationFrame` 1 回ごとに 100 件ずつ増やし、全件になるまで続ける (描画の合間に、画面が反応する)。途中で、フォルダ・検索・並べ替えなどを替えたら (`resetKey` が変わったら)、続きをやめる。ボタンは、増やしているあいだは押せなくする (`disabled`)。
- 表示の文言は変えない (「あと N 件」の N が、減っていく)。`すべて表示` の目的 (Ctrl+F で全件を探す) は、変わらない。
- 通常のスクロールでの増加 (1 回 `pageSize` 件) は、そのまま。
- テスト: 「すべて表示」を押したあと、1 フレームごとに 100 件ずつ増える (`requestAnimationFrame` をモック)。途中で `resetKey` が変わると止まる。全件になると、ボタンが消える。

## C. 詳細ページのフォルダのボタンの hover の丸の大きさ

### 現象
詳細ページで、hover の丸が、ブックマークの丸と同じ大きさにならず、しかもポストによって大きさがまちまち。

### 原因 (推測。実機の画像と v35 の実装から)
v35 は、ブックマークのボタン (`bm`) の `getBoundingClientRect()` の**幅**をそのまま使った。詳細ページでは、ブックマークのボタンの中に、数字 (「6,837」など) が入っていて、**幅が数字の桁数で変わる**。そのため、丸の大きさがポストごとにまちまちになる (数字のないポストでは、丸が小さく、数字の多いポストでは大きい)。

### 直し方 (`src/content/buttons.ts`)
- 大きさは、ブックマークのボタンの**幅ではなく、高さ**に合わせる (数字の桁数に左右されない)。丸の直径 = ブックマークのボタンの `height` (`getBoundingClientRect().height`)。幅は使わない。下限 34px、上限 64px は、そのまま。
- さらに確実にするため、ブックマークのアイコン (`svg`) の祖先をたどり、`svg` より大きく、幅と高さがほぼ等しい (差が 2px 以内)、`border-radius` が大きい (50% または 999px 以上) 最初の要素があれば、その直径を使う (X の hover の丸の要素そのもの)。見つかったら、それが `height` より優先。見つからなければ、`height`。
- アイコンの大きさ (`font-size`) は、`svg` の高さに合わせる (v35 のまま)。
- 測り直しは、挿入時と `ResizeObserver` の通知のときだけ (v35 のまま)。数字が変わる (ブックマークの件数が増減する) ときの再測定でも、大きさは変わらない (高さ基準なので)。
- テスト: 幅だけが違う (数字の桁数が違う) ブックマークのボタンで、フォルダのボタンの大きさが同じになる。`border-radius` のある祖先があれば、それを使う。

## D. 設定の説明の改行 (実機の画像で、不自然な箇所を特定)

### 現象 (実機の画像)
- 「…可能性があります（法的な助言では / ありません）。オフにすると…」: かっこの**途中**で行が切れる。さらに、「ありません） 。」のように、全角の閉じかっこと句点のあいだに隙間が出る。
- 「この機能をオン / にしたときだけ求めます」: 「オンにしたときだけ」が途中で切れ、行が不自然に短く終わる。

### 原因
- 文の途中に全角のかっこで補足を入れていると、`word-break: auto-phrase` が、かっこの中も文節で切る。全角の閉じかっこ「）」の右に空白があり、直後の「。」との隙間も目立つ (Windows の日本語フォントでは、全角の約物の詰め (`text-spacing-trim`) が効かない)。
- 1 文が長く、文節が多いので、切れ目が増える。

### 直し方 (文言を書き直す。ja のみ)
1. 次の 2 つのキーを、次のように書き直す (意味は変えない。かっこの補足を、独立した文にする)。
   - 全文取得の説明 (`fullTextSwitchDesc`): 「X で「さらに表示」と省略されたポストを保存すると、そのポストのページを裏のタブで開き、全文を読んで閉じます。1 件ごとに 4〜8 秒の間隔をあけ、いま見ているタブには触れません。X の規約上、自動化されたアクセスとみなされる可能性があります。これは法的な助言ではありません。オフにすると、省略された分だけを保存します。」
   - 画像のキャッシュの説明のうち、許可の文 (キーは `imageCache` 系で、「初めてオンにするとき、Chrome が「pbs.twimg.com（X の画像サーバー）へのアクセス」の許可を求めます。許可は、この機能をオンにしたときだけ求めます。」を持つもの): 「この機能を初めてオンにすると、Chrome が pbs.twimg.com へのアクセスの許可を求めます。pbs.twimg.com は、X の画像サーバーです。オフのままなら、許可は求めません。」
2. ほかにも、**文の途中に全角のかっこの補足があり、かつ画面で長い文になる説明** (設定、確認の画面、トースト、案内。ボタンや見出しのような短いラベルは対象外) を ja のメッセージから探す (`（` を含む `message` のうち、40 字を超えるもの)。見つかった分は、同じ方針で、補足を独立した文にする。直した件数と、直したキーを、報告に書く。意味は変えず、新しい情報は足さない。
3. `.setting-desc` と `.muted` の `text-wrap: pretty` をやめ、`text-wrap: wrap` (既定) に戻す。見出しとラベルの `balance` は残す。`word-break: auto-phrase` と `line-break: strict` は、そのまま。
4. 他の言語 (en、zh_CN など) は変えない。

### テスト
- ja の `fullTextSwitchDesc` とキャッシュの許可の文に、全角のかっこ (`（`、`）`) がない。直したキーのテストの期待値 (文言を確かめているテスト) を、新しい文言に合わせる。
- 8 言語のキーがそろう (`i18n.test.ts`)。
