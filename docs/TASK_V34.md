# TASK v34: 管理画面の軽量化 (段階表示、二乗の処理の解消、描画の省略)

v33 が終わったあとに実施する。保存データの形は変えない。必須の権限は増やさない。外部通信もしない。

## 目的
保存が 5,000 件を超えると、管理画面とサイドパネルが重い。原因は、一覧が **全件を DOM に描いている** こと (`src/manager/App.tsx` の `rows` が `shown.map`)。さらに、カードごとに `shownIds.includes(focusId)` を回していて、全体で件数の二乗の処理になっている。

**描画する件数を、最初は少なくし、下へ進むと増やす。** 検索・絞り込み・並べ替え・選択・件数の表示は、いまどおり全件のデータに対して動かす (描画する件数とは切り離す)。

## 決まっている方針 (ユーザーの判断)
- 軽量化は 1 (段階表示)、2 (`includes` の修正)、3 (`content-visibility`) で進める。
- 検索への影響はない。ただし、ブラウザの Ctrl+F と、↓ キーの移動に対処する (下の B と C)。
- 4 (自動取り込み中の再読み込みの間引き) と 5 (一覧に小さい画像を使う) は、この版に入れない。

## A. 段階表示 (`src/manager/App.tsx`)

- 描画する件数 `renderCount` を状態に持つ。初期値は **ビューごと**: ポスト表示 30、リスト表示 60、グリッド表示 60 (サイドパネルは 30)。定数にして、調整しやすくする。
- 一覧の末尾に、監視用の要素 (センチネル) を置き、`IntersectionObserver` で、末尾の手前 (`rootMargin` は画面の高さの 1.5 倍) に入ったら、`renderCount` を 1 回分 (初期値と同じ件数) 増やす。`IntersectionObserver` が無い環境 (jsdom など) では、末尾のボタンで増やす。
- `renderCount` を初期値に戻すとき: フォルダ・スマートビューを替えたとき、検索語・絞り込み・並べ替えを替えたとき、表示 (ポスト / リスト / グリッド) を替えたとき。保存データが変わっただけの再読み込み (自動取り込み中など) では、戻さない (スクロール位置が飛ぶため)。
- 描くのは `shown.slice(0, renderCount)`。`shown` (全件の結果) と `shownIds` (全件の ID) は、これまでどおり全件で持つ。選択 (`selected`)、全選択、Shift 選択の範囲 (`rangeIds`)、`targetIds`、件数の表示 (「N 件」「N 件中 M 件」) は、全件のデータで動かす。
- 描画した件数が全件より少ないときだけ、一覧の末尾に次を出す (v33 の改行の規則に従う。1 行、nowrap):
  - 残りの件数と、「すべて表示」ボタン。押すと、`renderCount` を全件にする。確認のダイアログは出さない。Ctrl+F で全件を探したい人のための入口。
  - 新しい文言 (8 言語): `listRemaining` (あと $COUNT$ 件)、`listShowAll` (すべて表示)。ボタンは 10 字前後まで。
- 空の表示 (`empty`) とフォルダが空の画面は、変えない。

## B. ↓ / ↑ キーの移動 (`onListKeyDown`)
- 次のカードが未描画のとき (`shownIds` にはあるが DOM にない) は、`renderCount` を、その位置 + 初期値の件数まで増やし、描画のあとでフォーカスする (`useEffect` / 次のフレームで)。
- 末尾の手前 (残り 5 件以内) に移ったときも、先に増やす。
- Home / End に相当する操作が既にあれば、End は「すべて表示」と同じにする。なければ足さない。
- 全選択 (`Ctrl+A`) は、描画されていない分も含めて選ぶ (これまでどおり `shownIds` 全件)。選択の件数の表示は、全件の数。

## C. 二乗の処理の解消
- `tabbable={focusId && shownIds.includes(focusId) ? … }` を、カードごとに計算しない。一覧の側で 1 回だけ `tabbableId` を決める (`focusId` が `shownIds` にあればその ID、なければ先頭)。`shownIds` を `Set` にする必要があるなら、`useMemo` で 1 回だけ作る。
- `shownIds` と `shown` は `useMemo` で、`shown` が変わるときだけ作り直す (いまは毎回の描画で作っている)。
- 同様に、カードごと (または一覧の描画ごと) に、全件を走査している箇所がないか確認する (`folderOf`、`selected.has` は定数時間なので対象外)。見つかったものを直し、報告に書く。
- `Card` を `memo` にする。ただし、親が毎回新しい関数 (`onSelect` など) を渡すと、`memo` が効かない。効かせるなら、`b` の ID を引数にした安定した関数を親に 1 つだけ作り、`Card` に ID を渡す形にする。効果が確認できない (テストで再描画の回数を数えて、減らない) 場合は、`memo` を入れず、報告に書く。

## D. 描画の省略 (`static/manager.css`)
- ポスト表示・リスト表示・グリッド表示のカード (`.card` に相当) に、`content-visibility: auto` と `contain-intrinsic-size: auto <高さの目安>px` を付ける (画面外のカードの描画を省く)。高さの目安は、ビューごとに、ポスト表示 320px、リスト表示 88px、グリッド表示 260px 程度。`auto` を付けて、一度描いた高さを記憶させる。
- フォーカス・キーボードの移動・選択・ドラッグ・画像のビューアが、これで壊れないこと (`content-visibility: auto` の要素も、フォーカスは受けられる)。壊れる箇所があれば、`content-visibility` を外して報告する。
- 画像の `loading="lazy"` は、そのまま。画像キャッシュ有効時の `MediaImg` は、描画された分だけ読む (A により、画面外の分は描かれない)。画像に `decoding="async"` を足す。

## 変えないもの
- `queryBookmarks` と検索の仕様、並べ替え、絞り込み、選択、削除、ドラッグ、ビューア、仕分けモード、自動取り込み、保存データの形。
- 件数の表示 (全件のデータから出す)。
- 自動取り込み中の再読み込みの間引きと、小さい画像の利用は入れない。

## 守ること
- 保存データの形は変えない。必須の権限は増やさない。外部通信はしない。
- 新しい文言は `listRemaining`、`listShowAll` の 2 つだけ。8 言語すべてに入れる。
- スクリーンショットは撮らない・足さない。

## テスト
- 5,000 件のデータで、初期の描画が `renderCount` 件だけ (DOM のカードの数)。
- 末尾のセンチネルが見えるとき (テストでは、`IntersectionObserver` をモックして発火)、`renderCount` が増える。増やしたあとも、全件を超えない。
- フォルダ・検索・並べ替え・表示を変えると、`renderCount` が初期値に戻る。保存データだけが変わったときは、戻らない。
- 検索語で絞り込むと、全件のデータから一致を探す (描画外のポストにも一致する)。「N 件中 M 件」が、全件から出る。
- 全選択が、描画されていない分も含めて選ぶ。Shift 選択の範囲が、描画されていない分にまたがっても正しい。
- ↓ キーで、描画の末尾の次へ進むと、描画が増えてフォーカスが移る。
- 「すべて表示」で、全件が描画される。残りの件数が表示される。全件を描画済みなら、ボタンは出ない。
- `shownIds.includes` の呼び出しが、カードごとに起きない (一覧の描画で、定数回)。
- 文言: 8 言語のキーがそろう (`i18n.test.ts`)。ボタンの文言が 10 字前後を超えない。
- 既存のテストが通る。

## 実機で確認する項目 (`docs/MANUAL_TEST.md` に v34 の節を足す)
- 5,000 件を超える保存の状態で、管理画面を開く。v1.1.1 より、開くまでの時間が短く、スクロールが軽い (体感でよい。できれば、開くまでの秒数を記録する)。
- 下へスクロールすると、途中でちらつかず、続きが出る。
- 検索語を入れる。描画外にあるポストも、検索結果に出る。
- 全選択 (Ctrl+A) の件数が、全件を指している。
- ↓ キーを押し続けて、描画の末尾を超えて進める。
- 「すべて表示」を押して、Ctrl+F で探せる (重くなる場合は、その旨を報告する)。
- 画像キャッシュを有効にした状態でも、軽い。
