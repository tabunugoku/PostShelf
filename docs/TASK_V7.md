# 追加タスク (v7): X のテーマに合わせた配色 / 管理画面の再設計 / x.com 変更への自己診断

前提: v5 までは `claude/serene-johnson-j5tpe7` で実装済み、v6 (アイコン組み込み) は `docs/TASK_V6.md`。続きで作業する (最初に `origin/main` をマージ)。v6 を先にコミットしてから v7 に進む。

基準にする画面: `docs/mockups/proposal-v6.html` (ブラウザで開く。タブ版 920px、サイドパネル版 400px、グリッド表示)。配色の基準は X の画面 (黒 / 白、アクセントの青)。

## A. 配色を X のテーマに揃える
1. トークンは `static/manager.css` の変数に集約し、manager / サイドパネル / popup / x.com に注入する UI で共有する。値は次を基準にする
   - ダーク: 背景 `#000000`、面 `#16181c`、枠 `#2f3336`、副文字 `#9aa4ad`、本文 `#e7e9ea`
   - ライト: 背景 `#ffffff`、面 `#f7f9f9`、枠 `#eff3f4`、副文字 `#536471`、本文 `#0f1419`
   - アクセント: アイコン・リンク・選択の強調は `#1d9bf0`。文字の載る塗り (ボタン、バッジ) は白文字で 4.5:1 を満たす `#0f6fb3` 以上の濃さにする
2. x.com に注入するポップオーバーとボタンは、今まで通り X の実際のテーマ (ライト / ダーク / ダーク青) を `body` の計算済みスタイルから判定して追従する。管理画面は OS の `prefers-color-scheme` に追従する
3. X のロゴ・商標は使わない。色と雰囲気を合わせるだけにする
4. 文字は 14px 以上、コントラスト 4.5:1 以上 (既存の基準を維持)

## B. タブ版 manager の再設計
`docs/mockups/proposal-v6.html` の「1. タブ版」と「3. グリッド表示」に合わせる。

1. 左サイドバー: 「スマートビュー」(すべて / 未分類 [件数バッジ] / 最近の 7 日) とフォルダ一覧の 2 区画。下部に「サイドパネルで開く」「設定」
   - 「最近の 7 日」は `savedAt` が 7 日以内のもの。件数は保存データから計算する
2. フォルダの編集は行の「…」(hover で表示) から開くポップオーバーに移す。名前、アイコン、色 (色なしを含む) を編集できる。ヘッダーの編集パネルは廃止。ドラッグでフォルダの並べ替え (v4 の機能を維持)
3. ヘッダー: フォルダのアイコンと名前と件数、常設の検索 (本文と @ユーザー名)、並べ替えボタン (アプリ内メニュー、v5 のものを再利用)、表示切替 (ポスト / リスト / グリッドの 3 種)
4. 取り込み案内のバナー: 未取り込みの件数 (v5 D の計算を再利用) と「取り込み方法」。閉じると、次に新しい未取り込みが増えるまで出さない (閉じた時点の件数を保存して比較する)
5. 絞り込みチップ: 画像あり / 動画あり / リンクあり / 投稿者。投稿者はメニューから選ぶ (保存データにあるハンドルの一覧)。複数を組み合わせられる (AND)
   - `snapshot` に動画・リンクの有無が無ければ、`src/content/snapshot.ts` で保存時に `hasVideo` `hasLink` (真偽値のみ) を追加する。既存データはメディアの拡張子や URL から推定せず、未判定として「画像あり」だけ判定できればよい (未判定は絞り込みに出ない)。データモデルの変更は `docs/` に記載し、読み込み時に欠けていても動くようにする
6. カード: hover でチェックボックスと操作 (フォルダ変更 / 元のポストを開く / 削除)。選択すると上部に一括操作バー (v4 の機能を再利用)。削除は元に戻すトースト付き
7. グリッド表示: 3 列、カードの高さをそろえる。画像付きは先頭画像を見せる
8. 空の状態は「見つかりませんでした」と、次の操作の案内 (検索語を変える / 絞り込みを外す)。ポストが 1 件も無いときは、保存方法の案内
9. 表示は `localStorage` ではなく `chrome.storage.local` の設定に保存する (最後に開いたフォルダ、表示形式、並べ替え)

## C. サイドパネル版の再設計
`docs/mockups/proposal-v6.html` の「2. サイドパネル版」に合わせる。

1. ヘッダー: 現在のフォルダを 1 つのボタン (アイコン、名前、件数、下向き矢印) にして、押すとフォルダ一覧のメニューが開く。右に検索ボタンと「タブで開く」
2. その下に、横スクロールのフォルダチップ (未分類は件数バッジ)。サイドバーは出さない
3. カード: 余白を詰め、操作は右端の「⋮」に集約 (フォルダ変更 / 元のポストを開く / 削除 / 選択)。複数選択は「⋮」から開始、またはカードの長押し
4. 下部の固定ボタン「いま開いているポストを保存…」: アクティブなタブが `x.com/*/status/*` のときだけ表示する
   - 押すと、そのタブの content script にメッセージを送って、ポストのスナップショットを取得し、フォルダ選択 (共通コンポーネント) を開く
   - `chrome.tabs` を使うので `tabs` 権限が必要か検討する。`activeTab` や host 権限 (すでに x.com にある) で足りる場合は追加しない。足りない場合も、最小の権限だけ追加し、理由を `docs/PUBLISH.md` に書く
   - x.com 以外のタブでは非表示。スナップショットが取れない場合 (画面構造の変更など) は、短いエラー文を出して何も保存しない
5. 幅が 520px を超えたらタブ版のレイアウトに切り替わる。画面部品は共用し、重複した実装を作らない
6. サイドパネルを開いたまま x.com で保存した内容が反映される (v5 で実装済み。壊さない)

## D. x.com の画面構造の変更への自己診断 (自動更新はしない)
外部サーバーからセレクタを取得することはしない (外部通信なしの方針)。

### D-1. フォールバックと自己診断
1. `src/shared/selectors.ts`: 各要素 (`tweet`、`tweetText`、`userName`、`bookmark`、`removeBookmark`、`actionGroup` など) を、優先順の候補リストにする
   - 1 番目は今の `data-testid`
   - 2 番目以降は、言語に依存しない構造的な候補 (例: `article[role="article"]`、`[role="group"]` の中のボタン、`time` 要素の祖先など)。`aria-label` の文言には依存しない (X の表示言語で変わるため)
   - 候補が 1 つしか作れない要素は、その旨をコメントに書く
2. 取得関数 `queryFirst(root, key)` は、最初に見つかった候補と「何番目の候補だったか」を返す
3. 新規ファイル `src/content/health.ts`
   - x.com でポストが 1 件以上表示されたとき、および DOM の変化があったとき (スロットル 10 秒以上) に、必要な要素が見つかるか検査する
   - 結果は 3 状態: `ok` (すべて 1 番目の候補で見つかった) / `degraded` (フォールバックで見つかった要素がある) / `broken` (見つからない要素がある)
   - 結果を `chrome.storage.local` の `health` キーに保存する (検査時刻、状態、見つからなかったキー、フォールバックだったキー)。外部には送らない
4. `broken` のとき: 該当のポストには PostShelf のボタンを挿入せず、X 標準の動作には一切触れない。`buttonMode: 'replace'` は自動で `separate` と同じ動作 (横取りしない) になる。連動モードのクリックも行わない
5. 表示: popup と設定に状態を出す
   - `ok`: 何も出さない (設定画面に「正常 (最終確認の時刻)」)
   - `degraded`: 「X の画面構造が一部変わっています。動作は続いています」
   - `broken`: 「X の画面構造が変わったため、一部の機能を止めています。診断情報を送ってもらえると直せます」 (D-2 へのボタン)
6. fixture テスト: `test/fixtures/` に 3 種 (通常 / `data-testid` を別名にしたもの / 要素が無いもの) を用意し、`ok` / `degraded` / `broken` の判定、`broken` でボタンが挿入されないこと、`replace` が横取りしないことを検証する

### D-2. 診断情報のコピー (ユーザーが押したときだけ)
1. popup と設定に「診断情報をコピー」ボタン。押すと content script に問い合わせて、次の内容を作る
   - 拡張のバージョン、`navigator.userAgent`、`chrome.i18n.getUILanguage()`、`health` の結果
   - 最初に見つかった `article` の DOM 構造の骨格。**タグ名、`role`、`data-testid`、`aria-*` の属性名 (値は含めない)、子要素の入れ子だけ**。テキスト、リンク、画像 URL、ユーザー名、ID は一切含めない。深さは 8 まで、全体で 6KB まで
2. コピーする前に、同じ内容をダイアログに表示して確認させる (「この内容がクリップボードにコピーされます。個人情報は含まれません」)。ユーザーが「コピー」を押したときだけコピーする
3. 「GitHub で報告」リンクを置く (新しいタブで Issue の新規作成画面を開くだけ。診断情報は自動で貼らない)。リンク先は `docs/PUBLISH.md` か設定ファイルで 1 か所に定義する
4. `.github/ISSUE_TEMPLATE/selector-broken.md` を作る (診断情報の貼り付け欄、X の表示言語、発生したページ)
5. テスト: 診断情報にテキスト・URL・ユーザー名が含まれないこと (fixture に実在風の文字列を入れ、出力に含まれないことを検証する)、サイズ上限、深さ上限
