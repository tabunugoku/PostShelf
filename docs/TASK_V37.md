## A. フォルダのボタンの丸を、X のブックマークの丸と同じ大きさにする

### 原因 (推測。実機の画像と v36 の実装から)
v36 の `sizeSeparateButton` (`src/content/buttons.ts`) は、丸の要素を **svg の祖先**の中から探す。しかし、X の hover の丸は、svg の祖先ではなく、**svg の兄弟** (svg と同じ親の中にある、絶対配置で、負の余白で svg より大きく広がる、`border-radius: 9999px` の空の要素) であることが多い (実機の DOM は未確認。X の操作アイコンの一般的な構造からの推測)。そのため見つからず、代わりに使ったブックマークのボタン全体の高さ (余白を含む) が、丸より大きかった。

### 直し方
- 丸の要素は、**bm の子孫全体**から探す (祖先だけでなく、svg の兄弟も含む)。条件は v36 と同じ: svg より大きい、幅と高さの差が 2px 以内、`border-radius` が 50% 以上か 999px 以上。複数あれば、svg に最も近い (DOM で svg と同じ親の中にある、またはその祖先にある) ものを優先する。見つかったら、その直径を使う。
- 見つからないときの代わりは、bm の高さではなく、**svg の高さ + 16px** (X の操作アイコンの丸は、アイコンの周りに約 8px ずつ広がる)。測れない (svg の高さが 0) ときは HIT (34px)。
- 下限 34px、上限 64px、アイコンの大きさ (svg の高さ)、測り直しの時機 (挿入時と ResizeObserver) は v36 のまま。
- コメントの「実機未確認」の前提を、上の推測に書き換える。
- テスト: svg の兄弟に丸の要素がある構造 (絶対配置、svg より大きい) で、その直径を使う。丸の要素が無いときは svg の高さ + 16px。bm の高さが大きくても (余白を含む)、それを使わない。幅だけが違うブックマークのボタンでは、同じ大きさ (v36 のテストは残す)。

### 実機で確認してほしい点
- タイムラインと詳細ページで、フォルダのボタンの丸が、ブックマークの丸と同じ大きさになる。詳細ページで、丸が右の共有のアイコンに触れない。

## B. 設定の説明を、1 文ごとに改行する (文言は変えない)

### 方針 (ユーザーの判断)
文言は変えない。表示で、文の終わり (ja では「。」) のあとで改行する。v25 の箇条書き (`.desc-list`) は、そのまま。

### 直し方
- `src/manager/ui.tsx` に、文字列を文に分けて、1 文を 1 行 (`<span class="desc-line">`、`display:block`) で描く小さな部品 (例: `Sentences`) を作る。分け方は `Intl.Segmenter(lang, { granularity: 'sentence' })` (`lang` は `document.documentElement.lang`。v33 で設定済み)。`Intl.Segmenter` が無い環境では、「。」の直後で分ける (「。」は前の文に残す)。前後の空白は落とす。1 文だけの文字列は、そのまま 1 行。
- 設定ページの説明に使う: `Settings.tsx` の `.setting-desc` で、`t()` の文字列をそのまま出しているもの (`buttonModeNote`、`acSettingsSwitchDesc`、`acSettingsNote`、`actionModeNote`、`dataMoveDesc`、`settingsResetDesc`、`deleteAllDesc`、`updateGuide`)、`FullText.tsx` の `fullTextSwitchDesc`、`ImageCache.tsx` の `cacheEnableDesc`、`cachePermNote`、`cacheBulkHelp`、`cacheRules`。`updateGuide` のリンクは、最後の行の末尾に続ける。
- 使わないもの: 状態の表示 (`FullText.tsx` の `role="status"` の行、エラー)、`.desc-list` と `desc-note`、ダイアログ、トースト、ポストの本文、サイドパネルの外の画面。
- 幅は v36 のまま (`max-width: none`)。1 文が長くて画面に収まらないときは、その文の中で折り返す (`word-break: auto-phrase` と `line-break: strict` は、そのまま)。
- テスト: ja で、`fullTextSwitchDesc` が 4 行 (「。」の数) に分かれ、行をつなげると元の文字列と同じ (文字が増減しない)。`Intl.Segmenter` を消しても、同じ結果。en でも、文の数だけ行になる。`updateGuide` のリンクが最後の行にある。文言のテストは変えない。

### 実機で確認してほしい点
- 設定の説明が、1 文ごとに改行される (「長いポストの全文を取得する」の説明が 4 行)。文の途中で切れない (幅 1,600px 以上)。

## C. v36 のコードレビューの指摘

1. `src/manager/App.tsx` の段階表示の効果のコメント「原因は特定できていない」を、v36 で特定した原因 (センチネルが遅れて現れ、効果が再実行されなかった) に合わせて書き直す。
2. 「すべて表示」で増やしているあいだ (`expanding`) は、センチネルの効果 (IntersectionObserver と scroll / resize の監視) を付け直さない (1 フレームごとに作り直し、測り直すのは無駄)。`expanding` が終わったら、元どおり付ける。
3. 「すべて表示」の効果は、`growTo` が使う `shown` も依存に入れる (途中で保存データが変わったとき、古い件数を使わない)。
4. `static/manager.css`: v36 で `.muted` の `text-wrap: pretty` を全体で外した。指示書の範囲は設定ページだけなので、`.muted` の `pretty` は戻し、設定ページの中 (`.setting-group .muted`、`.setting-desc`) だけ `text-wrap: wrap` にする。
5. `test/v36.test.tsx`:
   - B のテストの `cancelAnimationFrame` の差し替えは、`frames` の位置ではなく、ID と関数の対応 (`Map`) で消す (`runFrame` で配列を空にすると、古い ID が新しい関数を消すため)。
   - リスナーの漏れのテストは、`addEventListener` を差し替えて止めず、本物を呼んだうえで数える (`mockImplementation` ではなく、`spyOn` の記録)。数えるのは、段階表示の効果が付ける `scroll` / `resize` だけ (付けた関数を記録し、同じ関数が外されたか)。`<= 0` ではなく、付けた数と外した数が等しいことを確かめる。
