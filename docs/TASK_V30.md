## A. 設定 (`src/manager/Settings.tsx`、`static/manager.css`)

### A-1. 設定の検索
- 設定ページの上部 (目次 `.settings-nav` の上) に、検索欄を置く (`type="search"`、`placeholder` と `aria-label` は「設定を探す」)。
- 入力すると、各設定の行 (`.setting`) のうち、**項目名または説明の文字が一致する行**だけを残す。一致しない行は `hidden` にする (要素は消さない。状態を失わないため)。一致する行が 1 つもないグループ (`fieldset.setting-group`) は、見出しごと隠す。目次 (`.settings-nav`) も、一致のあるグループだけを残す。
- 比べるときは、大文字小文字と全角半角を区別しない (既存の検索 `query.ts` の正規化があれば、それを使う)。
- 入力中は、「「語」に一致 N 件」を `role="status"` で出す (検索欄の下の 1 行)。0 件なら「見つかりませんでした」(既存の `notFoundTitle` を使ってよい)。空に戻すと、すべて元に戻る。
- 「初期化と削除」(`danger-zone`) のグループは、検索の対象に含めてよいが、見た目は変えない (赤の枠のまま)。

### A-2. 変更後の「保存しました」
- 設定ページのスイッチ・選択を変えて保存されたとき (この画面での変更のみ。他のタブでの変更の通知では出さない)、ページの右上 (見出しと同じ行) に「変更を保存しました」を 2 秒出して消す (`role="status"`、`aria-live="polite"`)。場所を空けておき、出入りで周りが動かないようにする。
- 出さない: データの書き出し・読み込み、初期化、削除 (それぞれ専用の結果表示がある)。
- 新しい文言 (8 言語): `settingsSearch` (設定を探す)、`settingsMatchCount` (「$QUERY$」に一致 $COUNT$ 件)、`settingsSaved` (変更を保存しました)。

## B. 取り込み後に、仕分けへつなぐ
- x.com の自動取り込みパネル (`src/content/autocollectPanel.ts`) の `done` の状態で、取り込んだ件数 (`imported`) が 1 以上のとき、主ボタン「管理画面を開く」(`acBtnOpenManager`) を「仕分ける」に替える。押すと、管理画面を `#triage` で開く (v29 の入口。未分類が 0 件なら、未分類の表示だけが開く)。`imported` が 0 のときは、いまのまま。
- 管理画面にある、自動取り込みの結果の帯 (v22 で、閉じたら保存してある記録も消すようにしたもの。`src/manager/AutoCollect.tsx` または `App.tsx` を探す) にも、`imported` が 1 以上のとき「仕分ける」ボタンを足す。押すと、「未分類」を選んで仕分けモードを始める (サイドパネル版の帯では、仕分けモードがないので「未分類」を開くだけにする)。
- 新しい文言 (8 言語): `acBtnTriage` (仕分ける)。

## C. 初めて開いたときの案内 (`src/manager/App.tsx` の `empty-state`)
- 保存が 0 件のときの案内 (`noPostsTitle` / `noPostsHint`) を、2 つの手順にする。

- 検索で一致なしの画面 (`notFoundTitle`) と、フォルダが空の画面 (`empty`) は、変えない。
- 新しい文言 (8 言語): `onboardTitle` (はじめましょう)、`onboardStep1` (x.com のポストで、フォルダのボタンを押す)、`onboardStep2` (いまのブックマークを取り込む)、`onboardImport` (取り込む)。使われなくなる `noPostsHint` は、他で使っていなければ削除せず残してよい。

## D. 検索語の強調 (`src/manager/PostText.tsx`、`src/manager/Cards.tsx`)
- 検索語があるとき、ポストの本文の中で一致した語を `<mark>` で強調する。複数の語 (空白区切り) があれば、それぞれを強調する。大文字小文字と全角半角は区別しない (一致の判定は、一覧を絞り込む `query.ts` と同じ正規化にする)。
- リンクの部品 (`g.t === 'link'`) では、`href` や属性は変えず、表示の文字だけを分けて強調してよい。HTML としては解釈しない (部品ごとに要素を作る。いまの方針のまま)。
- 色は、ライト / ダークの両方で、本文の文字に対してコントラスト 4.5:1 以上にする (`static/manager.css` のトークンを使う。既存のコントラスト自動テストに足す)。`mark` の下線や太字には頼らない。
- 本文が「たたまれている」(`clamp`) とき、一致が隠れた行にあっても、一致があることがわかるようにしなくてよい (この版では対象外)。
