v33・v34 の開発版を実機 (保存 5,056 件) で確認して、残った不具合の修正。保存データの形は変えない。必須の権限は増やさない。外部通信もしない。

実機の結果: 軽さは改善した。サイドパネル、スクロール位置は直った。以下が残っている。

## A. 「すべて」ビューで、段階表示が 30 件で止まる

### 現象
「すべて」を下までスクロールすると、「あと 5026 件 / すべて表示」が出て、続きが読み込まれない (30 件のまま)。同じ 5,056 件の「未分類」「最近の 7 日」では、続きが読み込まれ、問題ない。

### 原因 (不明。読んだだけでは特定できていない)
`src/manager/App.tsx` の段階表示 (`sentinelRef`、`IntersectionObserver`、`growTo`、`resetKey`) が「すべて」だけで働かない。候補:
1. 「すべて」で `resetKey` が描画のたびに変わり、`rcState.key === resetKey` が成り立たず、`renderCount` が毎回 `pageSize` に戻る (増やしても戻される)。
2. 「すべて」では、センチネルの `IntersectionObserver` が、初回の描画 (読み込み前の空の一覧) で付かないまま、再実行されない。
3. 「すべて」の一覧の親要素の構造が違い、観察の対象が画面の外にあると判定される。

### 直し方
1. まず、jsdom のテストで再現する。「すべて」(`ALL_FOLDER_ID`) と「未分類」の両方で、`IntersectionObserver` をモックし、センチネルが交差したときに `renderCount` が増えることを確かめる。再現できた原因を直し、**原因をコミットメッセージと報告に書く**。
2. 原因に関係なく、IntersectionObserver だけに頼らない。**スクロールの確認を足す**: `window` の `scroll` と `resize` (passive、`requestAnimationFrame` で間引く) で、センチネルの `getBoundingClientRect().top` が `window.innerHeight * 2` 未満なら、`growTo` を呼ぶ。描画のたびに (増やしたあとにも) 同じ確認をして、センチネルが遠くなるまで続けて増やす。観察と確認のどちらでも増えても、二重に増えないよう、1 回の増加は `renderCount` を基準にして決める (すでに増えていたら何もしない)。
3. テスト: 「すべて」「未分類」「最近の 7 日」の 3 つのビューで、一覧の末尾までスクロールしたとき (`IntersectionObserver` なしの環境で、`scroll` イベントを発火し、センチネルの矩形をモック) に、`renderCount` が増える。フォルダを替えると初期値に戻る。保存データだけが変わったときは戻らない。

## B. 設定の説明の改行 (残っている不自然な折り返し)

### 現象
v33 で語の途中の折り返しは大きく減った。残っているのは、「オフにすると、た / たまれた分だけを保存します」(「たたまれた」の途中で改行) など。

### 原因
1. 説明の最大幅が `static/manager.css` の `.setting-desc { max-width: 40em }` で、画面の幅 (1,600px 以上) に対して狭い。行が短いので、折り返しが増える。
2. 「たたまれた」のようなひらがなの連続は、ブラウザの単語の区切りの辞書で、途中で切られることがある (`word-break: auto-phrase` の限界)。

### 直し方
1. `.setting-desc` の `max-width` を `52em` にする (他の説明文の最大幅も確認して、同じ程度にそろえる: `.muted`、`.empty-state p`、`.pre` など、文章を出す要素で 40em 前後のもの)。ポスト本文の幅は変えない。
2. ひらがなの連続が途中で切られる文言を、ja だけ言い換える。見つけた分すべて (少なくとも次の 1 つ):
   - 「X で「さらに表示」とたたまれたポストを保存すると…」「オフにすると、たたまれた分だけを保存します」の「たたまれた」を、**「省略された」** にする (全文取得の説明。キーは `fullTextDesc` 系。他のキーにも同じ語があれば同様に直す)。意味は変えない。
   - ほかにも、実機で語の途中で切れる箇所があれば、同じ方針で直す (ひらがなが 5 字以上続く語を点検して報告する)。
3. 英語など、ほかの言語は変えない。

### 確認
- CSS の `max-width` が `52em` になっている (テスト)。ja の文言に「たたまれた」が残っていない (テスト)。
- 実機: 設定の長い説明で、語の途中で折り返さない。

## C. x.com のポスト詳細で、フォルダのボタンの hover の丸が小さい

### 現象
ポストの詳細ページで、ブックマークのボタンにマウスを乗せると、大きい青い丸 (約 58px 幅) が出る。フォルダのボタンの丸は、それより小さい (約 38px)。位置と高さは、直った。タイムラインでは、同じ大きさに見える。

### 直し方 (`src/content/buttons.ts` の `createSeparateButton` / `injectButtons`)
- 固定の `HIT = 34` ではなく、**隣のブックマークのボタンの大きさに合わせる**。挿入するときに、ブックマークのボタン (`bm`) の `getBoundingClientRect()` を測り、幅・高さ (小さいほうに合わせた正方形、または同じ寸法) を、フォルダのボタンの `width` / `height` に使う。下限は `HIT` (34px)。上限は 64px。
- アイコンの大きさ (`font-size: 19px`) も、ブックマークのアイコン (`svg`) の `getBoundingClientRect()` の高さに合わせる (下限 19px)。
- 大きさは、ボタンを挿入したあと (X が再描画したときと、ウィンドウの大きさが変わったとき) に、測り直す。X の DOM の変化で何度も再描画されるので、測るのは挿入と、`ResizeObserver` (あれば) の通知のときだけにする。測れなかった (幅 0) ときは、`HIT` のまま。
- `border-radius: 50%` と、左の余白 (`GAP`)、`align-self: center` は、そのまま。丸が大きくなった分、重ならないように、`margin-left` を丸の大きさの差の半分だけ減らさず、`GAP` のままにする (詳細ページで数字に重ならないことを確認する)。
- 想定: 詳細ページの `bookmark` ボタンは、X の hover の丸を、ボタンの外側 (約 58px 幅) に持つ。測った幅が、その外側の大きさであること (実機未確認。コメントに明記)。

### 確認
- `getBoundingClientRect` をモックした要素で、測った大きさがボタンに反映される。測れないときは 34px のまま。下限と上限が効く。
- 実機: 詳細ページで、フォルダのボタンの hover の丸が、ブックマークのボタンの丸と同じ大きさになる。タイムラインで、丸が大きくなりすぎない。
