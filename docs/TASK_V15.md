## A. 「未分類」で保存できるようにする (制限の撤廃)
### 現状 (実機で確認済み)
x.com のフォルダ選択ポップオーバーでは、フォルダが 1 つもない状態だと「フォルダがありません」と出て、新しいフォルダを作らないと保存できない。フォルダがあっても、必ずどれかのフォルダにチェックを入れないと保存できない (すべて外すと保存が解除される)。コードの原因は、`src/shared/folderPicker.ts` が「未分類」の行を出さないことと、`src/shared/storage.ts` の `setBookmarkFolders` が、フォルダ ID が空だと保存を削除すること。一方、manager のフォルダ選択 (`pickerFolders`) には「未分類」の行がある。

### やること
1. フォルダ選択 (`createFolderPicker`) の先頭に、常に「未分類」の行を出す。これは、x.com のポップオーバー、manager の「フォルダを変更」、サイドパネルの「いま開いているポストを保存」の 3 か所で共通に使うので、共通部品で直す
   - 「未分類」はフォルダが 1 つもなくても表示する。チェックを入れるだけで保存できる (新しいフォルダを作らなくてよい)
   - 「未分類」は、他のフォルダと同時には選べない。未分類にチェックを入れると、他のフォルダのチェックは外れる。他のフォルダにチェックを入れると、未分類のチェックは外れる
   - アイコンと名前は、manager の `inboxView` と同じもの (名前は `inboxName`、アイコンは `ti-inbox`)
2. `setBookmarkFolders` の挙動
   - `INBOX_ID` だけを渡したときは、そのポストを「未分類」として保存する (削除しない)
   - 保存の解除は、フォルダ ID が空のときではなく、明示的な操作にする。ポップオーバーに「PostShelf から外す」ボタン (保存済みのときだけ表示) を足す
   - 保存済みのポストで、最後に残ったフォルダのチェックを外したときは、保存が解除されるのではなく、「未分類」になる (manager の `removeFromFolders` と同じ挙動。未分類しか無いポストを「外す」意味はない、という既存の考え方に合わせる)
3. ポップオーバーの表示
   - 未保存のポストで開いたとき、「未分類」の行は未チェックの状態
   - 「未分類」にチェックを入れた直後に、保存される (他のフォルダと同じ即時保存)。保存済みであることがボタンの見た目 (保存済みバッジ) に反映される
   - 空のときの文言 `noFolders` (「フォルダがありません」) は、「未分類」の行が常にあるので、実際には出なくなる。文言は、「フォルダを作ると、ここに並びます」のように、「未分類」を前提にした言い方に変える (8 言語)
   - 「新しいフォルダ」の入力が空のまま「追加」を押したときのエラー (「フォルダ名を入力してください」) は、そのままでよい。ただし、保存の操作をこの入力に依存させない
4. 連動モード (X のブックマークも付ける) との関係: 「未分類」での保存でも、これまでどおり X 側のブックマークを付ける。「PostShelf から外す」を押したときは、X 側の解除を、これまでの「すべてのフォルダから外したとき」と同じ扱いにする
5. テスト (vitest + jsdom)
   - フォルダが 0 件のとき、「未分類」の行が出る。チェックで保存され、`folderIds` が `[INBOX_ID]` になる
   - 「未分類」と他のフォルダが排他になる (どちらからでも)
   - 保存済みのポストで最後のフォルダを外すと、「未分類」になる (削除されない)
   - 「PostShelf から外す」で保存が削除される
   - manager の「フォルダを変更」とサイドパネルの保存でも、同じ「未分類」の行が使える
6. `docs/MANUAL_TEST.md` に追加: フォルダが 0 件の状態で、x.com のポップオーバーから「未分類」にチェックして保存できること、保存後に管理画面の「未分類」に出ること、フォルダを作って移すと「未分類」から外れること、「PostShelf から外す」で保存が消えること

## B. ブックマークの自動取り込み (「方針の例外」であることを守る)
### 方針の変更 (必ず `CLAUDE.md` と文書に反映する)
これまでは「自動スクロールで大量取得しない」としていた。この機能に限り、次の条件でのみ例外とする。**条件を満たさない自動化は、引き続き入れない。**
- ユーザーが、開始の確認ダイアログで同意して「始める」を押したときだけ動く。インストール直後、アカウントの切り替え直後、ページを開いただけでは、**自動では始まらない** (案内を出すだけ)
- x.com の非公開 API や GraphQL を直接呼ばない。ユーザーが見ているページを、ユーザーの代わりにスクロールして、画面に出たポストの DOM を読むだけ
- 速度を抑える (待ち時間を入れる)。いつでも一時停止・停止できる。X が制限やエラーを出したら自動で止める
- 外部サーバーへの送信は、これまでどおりなし
- `CLAUDE.md` の「守ること」を次のように改める: 「自動スクロールで大量取得しない」 → 「自動スクロールによる取り込みは、ユーザーが確認ダイアログで同意して開始した取り込みに限る (速度を抑え、一時停止・停止ができ、X の制限を検知したら止める)。それ以外の自動スクロールは入れない」
- `README.md`、`docs/FAQ.md`、`docs/INSTALL.md`、`docs/PUBLISH.md` に、この機能が X の規約上の「自動化されたアクセス」とみなされる可能性があること、アカウントの制限などが起きても作者は責任を負えないことを、正直に書く。根拠は `reports/類似拡張機能の比較とX規約対応.md` (リポジトリに入れていなければ、要点だけを文書に書く)
- ユーザーがこの機能を使わないと決められるようにする: 設定に「自動取り込みを使う」のスイッチ (既定はオン) を置く。オフにすると、案内も開始ボタンも出ない

### B-1. 取り込みの本体 (content script)
場所: `src/content/autocollect.ts` (新規)。対象のページは `/i/history` の「ブックマーク」タブだけ (`/i/history/likes` では動かさない。`isBookmarksPage` を使う)。
1. 開始と制御
   - 開始は、確認ダイアログ (B-3) の同意の後。管理画面から始めるときは、`chrome.storage.local` のコマンド (例: `collectCommand: { type: 'start', speed, cap, accountId }`) を書き込み、x.com の `/i/history` のタブを開く (または、すでにそのタブがあればそれを使う)。content script はストレージの変更を監視してコマンドを受け取る。**新しい権限 (`tabs` など) は足さない**
   - ページ上の進捗パネルから、一時停止、再開、停止ができる。管理画面からも同じコマンドを送れる
   - 開始の 3 秒前に、「3 秒後に始まります。キャンセル」の表示を出す (同意したあとの取り消し用)
2. スクロールの動かし方
   - 画面の高さの約 8 割ずつスクロールする。スクロールのあと、新しいポストが出る (`MutationObserver`) か、一定時間たつまで待つ
   - 待ち時間は、「ゆっくり」(既定): スクロールごとに 2〜4 秒のランダムな待ち。「標準」: 1〜2.5 秒
   - X の一覧は、画面外のポストを DOM から外す (仮想化) ことがあるので、スクロールのたびに、いま DOM にある `article` を読み、取りこぼしがないようにする。読むのは既存の `collectVisible` の仕組みを再利用する
   - 同じ取り込みの中で、同じポストを二重に数えない (ポスト ID で管理する)
3. 終わりの判定: 新しいポスト (取り込み済みを含む) が、5 回続けて出なかったとき、かつ読み込み中の表示が出ていないときに「完了」とする。実機で確認できていないので、判定の条件は定数にして、調整しやすくする
4. 一時停止と再開
   - 一時停止の条件: ユーザーの操作、タブが非表示になったとき (`visibilitychange`)、アカウントが変わったとき、X がエラーや制限を表示したとき、1 回の上限に達したとき
   - 再開は、ユーザーが押したときだけ。自動では再開しない
   - ページを再読み込みしたあとの再開: 一覧の先頭から、また同じ順にスクロールしていく。**取り込み済みのポストは、読み飛ばす (スキップ)**。スキップの間も、同じ速度を守る
5. X の制限やエラーの検知: 制限やエラーの表示 (例: 「問題が発生しました」「Rate limit exceeded」と再試行ボタン) のセレクタ候補を、`src/shared/selectors.ts` に候補リストで追加する (v7-D の `queryFirst`)。見つけたら、自動で一時停止し、「15 分以上あけてから再開してください」と表示する。**実機で確認できていない**ため、`docs/MANUAL_TEST.md` に未確認として書く
6. アカウント: 開始時のアカウント ID を記録し、取り込み中にアカウントが変わったら止める (v9 のアカウント判定を使う)。アカウントを判定できないときは、開始できない
7. 状態の保存 (`collectRun`): `{ status, accountId, startedAt, imported, skipped, failed, oldestSeenPostDate, speed, cap }` を `chrome.storage.local` に書く。管理画面の進行表示と、ページを閉じたあとの「前回の取り込み」の表示に使う

### B-2. 並び順を X と同じにする (最重要)
X のブックマークは、新しく追加した順で、下へスクロールするほど古くなる。PostShelf の「保存が新しい順」(`savedAt` の降順) でも、**同じ順で並ぶ**必要がある。取り込んだ時刻をそのまま `savedAt` にすると、最初に出てくる (いちばん新しい) ポストの時刻が最も古くなり、順番が逆になる。
1. 取り込みでは、`savedAt` を、取り込んだ時刻ではなく、一覧での位置から決める
2. 決め方 (案。結果が下の条件を満たせば、別の方法でもよい)
   - 取り込みの間、画面に出てきた順に、(ポスト ID、取り込み済みか) を記録する
   - 一時停止、完了、または一定件数ごとに、まだ値を決めていない新しいポストをまとめて整える。新しいポストが連続して並ぶ区間の、すぐ上にある取り込み済みのポストの `savedAt` を U、すぐ下にある取り込み済みのポストの `savedAt` を L とする
     - U と L の両方がある (U > L): 区間の n 件に、L と U のあいだを等間隔に割り当てる (`L + (U − L) × (n − i) / (n + 1)`、i は上から 0 始まり)。`savedAt` は小数でもよい
     - U だけがある (下にまだ取り込み済みがない): `U − (i + 1) × 1000` ミリ秒
     - L だけがある (いちばん上の区間): 取り込みの開始時刻を T として、`T − i × 1000` ミリ秒 (L より大きいことを確かめる。そうでなければ `L + (n − i) × 1000`)
     - どちらもない (初回): `T − i × 1000` ミリ秒
   - U ≤ L のとき (PostShelf のボタンで保存した日時が一覧の並びと合わないとき) は、`U − (i + 1)` ミリ秒で入れる。並びが多少ずれても、データは失わない
3. 満たすべき条件
   - 初回の取り込みで、PostShelf の「保存が新しい順」の並びが、x.com のブックマークの並びと一致する
   - 一時停止して再開しても (ページの再読み込みを挟んでも)、取り込み済みのポストは変わらず、新しいポストが X の並びの位置に入る
   - 途中で X 側に新しいブックマークが増えた場合 (一覧の先頭に新しいポストが出る) も、先頭の区間として、取り込み済みより上に入る
   - 手動の取り込み (いま見えている分だけ取り込む、既存の機能) も、同じ並び順の処理を使い、取り込み済みのポストはスキップする
4. 既存の取り込み (`addCollected` など) が `savedAt: Date.now()` を使っている箇所を、この処理に置き換える。既存のデータは変えない (移行しない)
5. テスト: 上の条件をそれぞれ、ポスト 20 件程度のフィクスチャで確認する (初回、途中で停止して再開、取り込み済みを挟んだ区間、先頭に新規が増えた場合、`U ≤ L` の場合、手動の取り込みとの組み合わせ)

### B-3. 画面 (`docs/mockups/auto-collect.html`)

### B-4. テスト (vitest + jsdom。タイマーは偽装する)
- 同意なしでは始まらない (開始の操作がない限り、スクロールが一度も動かない。案内バナーを出すだけ)
- スクロールの間隔が、速度ごとの範囲に収まる。一時停止中は、スクロールが動かない。再開で続きから動く
- 取り込み済みのポストはスキップされ、件数に数えられる
- 並び順 (B-2 の条件)
- 終わりの判定 (5 回続けて新しいポストがない)
- アカウントが変わったら止まる。タブが非表示になったら一時停止になる
- 制限やエラーの表示 (フィクスチャ) で、自動で一時停止になる
- 上限 (300 件) に達したら止まり、「続ける」で再開できる
- 通信: 取り込みの間に、`fetch` / `XMLHttpRequest` を一度も呼ばない (X の画面が自分で行う通信以外はなし)
- `/i/history/likes` と他のページでは動かない
