# TASK v22: 「画像あり」の絞り込みと、取り込みの結果の帯が閉じない不具合

v21 が終わったあとに実施する。2 つの不具合を直す。保存データの形は変えない。

## 1. 動画だけのポストが「画像あり」に出る
### 原因 (確認済み)
- `src/shared/query.ts` の `hasImage` が `snapshot.media.length > 0` だけで判定している。
- 動画のポストは、X が動画のサムネイルを画像として表示する。保存時の取得 (`src/content/snapshot.ts` の `media`) が、そのサムネイルを `media` に入れる。そのため、動画だけのポストも `media.length > 0` になる。

### 直し方
- `hasImage` を「`media.length > 0` かつ `hasVideo !== true`」にする。
- X では、1 つのポストに画像と動画は混在できない (画像は最大 4 枚、動画は 1 本または GIF 1 つ。第三者の資料による。X 公式のヘルプでは確認できていない)。ただし、動画の本数は将来増える可能性がある (2026 年 6 月に、動画 6 本のテスト投稿が報じられた)。そのため、動画の本数には依存せず、「`hasVideo` が真なら画像ではない」という書き方にする。
- `hasImage` を使っている場所をすべて調べ、同じ前提でそろえる (絞り込みのチップ、v20 の札の枚数、件数の表示、サイドパネル)。v20 の札が、すでに `hasVideo` で動画のポストに枚数の札を出さない作りなら、その動作が変わらないこと。
- 既存の保存データは書き換えない (判定のコードだけを直す)。

### 限界 (書いておく)
- v7 より前に保存したポストは `hasVideo` を持たず、動画でも「画像あり」に残る。`docs/MANUAL_TEST.md` と `docs/FAQ.md` の、v20 で書いた同じ限界の行に、「画像あり」の絞り込みも含まれることを足す。

## 2. 「取り込みが終わりました」の帯が、閉じても開くたびに出る
### 原因 (確認済み)
- 管理画面は、閉じたことを `useState` (`runClosed`、`src/manager/App.tsx`) だけに持っている。管理画面を開き直すと、この値が 0 に戻る。
- 一方、取り込みの記録 (`collectRun`) は `chrome.storage.local` に残り、`status: 'done'` のまま消えない。そのため、開くたびに `collectRun.updatedAt !== runClosed` が真になり、結果の帯が再び出る。
- x.com 側のパネルの `dismiss()` (`src/content/autocollect.ts`) も、画面の状態を消すだけで、保存済みの記録は残す。

### 直し方
- 終わった状態 (`done` と `stopped`) の帯を「閉じる」で、保存してある取り込みの記録も消す (`clearCollectRun`)。管理画面と x.com のパネルの、どちらで閉じても同じにする。進行中の状態 (`countdown`、`running`、`paused`、`limit`) は、閉じても記録を消さない (いまの動作のまま)。
- 別のタブ・別の画面が同じ記録を表示しているときも、記録が消えたら帯が消える (`onCollectRunChanged` で追従する)。
- 閉じずに放置した結果が、いつまでも出続けないよう、終わってから 24 時間たった `done` / `stopped` の記録は、管理画面を開いたときに表示しない (記録は、次の取り込みの開始で上書きされる)。
- 「取り込みを終えたアカウントの案内」(`offers` の `done`) と、取り込みの開始のしくみは、変えない。

## 守ること
