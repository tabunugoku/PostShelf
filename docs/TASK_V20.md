## 9. 動画と画像の札 (v20-A)
いまは、動画のポスト (サムネイルは動画の 1 コマ) と、画像のポストが、グリッド表示で同じ見た目になる。リスト表示とサイドパネルにも、メディアの種類の表示がない。

対象の画面は、管理画面のグリッド表示・リスト表示・ポスト表示 (X 風)、サイドパネルの 3 つの表示。同じ札の部品を共有して、見た目をそろえる。

- **動画**:
  - サムネイルの中央に、円形の再生ボタン (半透明の黒い円 + 白い三角)、左下に「動画」の札 (ビデオのアイコン付き)。
  - リスト表示 (サムネイルがない) では、行の右端に、青い塗りの「動画」の札を出す。
- **画像が 2 枚以上**:
  - サムネイルの右下に、「重なりのアイコン + 枚数」の札。
  - リスト表示では、行の右端に、画像のアイコンと枚数の札 (枠だけの控えめな見た目)。
  - 画像が 1 枚のときは、何も付けない (これまでどおり)。
- **動画のサムネイルがないとき** (古い保存分は `videoPoster` を持たない): 暗い単色の面に、再生ボタンと「動画」の札を出す。
- **判定**: すでに保存してある `snapshot.hasVideo` (絞り込みの「動画あり」と同じ印) を使う。新しい取得はしない。画像の枚数は `snapshot.media.length`。ただし、動画のポストの `media` に動画のサムネイルが含まれている場合は、画像の枚数として数えない (動画のポストには、枚数の札を出さない)。実際の保存データの形を確かめて、数え方を決める。
- 札の文字と、アイコンの色は、サムネイルの上でも読めるように、半透明の黒い背景に白で出す。ライト / ダークのどちらでも同じ。
- 札は、画面を読み上げる人にも分かるよう、`aria-label` (例: 「動画」「画像 3 枚」) を付ける。
- ポスト表示 (X 風) で動画を表示するときの、いまの見せ方 (クリックでビューアが開く、など) は変えない。再生ボタンは、見た目の印であり、ここで動画を再生する機能ではない。クリックしたときの動作は、サムネイル全体のいまの動作のまま。

### 決めておくこと (限界)
- **GIF**: X の GIF は、動画と区別できないので、「動画」の札を付ける。区別する工夫はしない。
- **古い保存分**: v7 より前に保存したポストは、`hasVideo` を持たず、動画かどうかが分からない。札を付けられない (未判定のまま)。この限界を、`docs/MANUAL_TEST.md` と `docs/FAQ.md` に 1 行ずつ書く。
- **動画の長さ**: 保存していないので、札に出さない。

## 10. サイドパネルの複数選択バー (v20-B)
- いまは、1 件を選ぶと、大きなボタンが 4 つ (フォルダに追加 / フォルダから外す / 削除 / 選択解除) 縦に並び、一覧が押し下げられる。
- v19 の 6 で決めた、管理画面の「N 件選択中 ⌄」のボタンと同じ形にする。サイドパネルでは、並べ替えの行に置く。押すと、4 つの操作が開く。何も選んでいないときは、このボタンを出さない。
- 一覧が、選択のたびに下へずれないこと。
- 削除の確認と、取り消しの通知、すでにあるキーボード操作は、変えない。
- 管理画面とサイドパネルで、選択の状態を扱う部品を共有している場合は、共有したまま、見た目だけを変える。

## A. メニューが切れる (v20-C)
スクリーンショットで確認できた不具合:
- サイドパネルのグリッド表示で、カードの「…」メニューが、パネルの左端で切れて、文頭が欠ける (「フォルダを変更」が「ルダを変更」に見える)。
- 管理画面のグリッド表示で、「フォルダ変更」のメニュー (フォルダの一覧) が、カードの枠に隠れて、一部しか見えない。

直し方:
- カードの「…」メニューと、「フォルダ変更」の一覧を、カードの内側ではなく、画面全体の最前面 (`position:fixed`、または `body` 直下の入れ物) に出す。カードの `overflow:hidden` に隠れないこと。
- 出す位置は、きっかけのボタンの近くを基準に、画面 (サイドパネルでは、その幅) の端に収まるよう補正する。右にはみ出すときは左へ、下にはみ出すときは上へ出す。
- スクロールやウィンドウの大きさの変更、Esc、外側のクリックで閉じる。いまの閉じ方を変えない。
- 管理画面のリスト表示とポスト表示、サイドパネルのリスト表示とポスト表示でも、同じ部品を使い、同じように収まる。

## B. 削除の確認の折り返し (v20-C)
- 「1 件のポストを PostShelf から削除しますか? X のブックマークは変更されません。」が、「ませ / ん。」と、1 文字だけ次の行に折り返す。
- 確認の幅を広げ (中身が 2 行に収まる幅)、`text-wrap:balance` などで、不自然な折り返しを避ける。ほかの確認の画面 (すべてのデータの削除、設定の初期化、アカウントのデータの削除) にも、同じ部品が使われていれば、同時に直る。

## 守ること
- 保存データの形、保存の動作、取り込みの動作は変えない。見た目と DOM の組み立てだけ。
- 必須の権限は増やさない。外部通信もしない。
- キーボード操作と、スクリーンリーダー向けの属性 (`aria-*`、`role`) を保つ。
- 色は、ライト / ダークのどちらでも読める。
- 新しい文言 (札の「動画」「画像 N 枚」の読み上げ文言など) は、8 言語すべてに入れる。既存のキー (「動画あり」など) があれば、再利用する。`npm run release:check` のキーの突き合わせが通ること。
- 文字列を直接比べているテストは、新しい見た目に合わせて直す。

## テスト
- 9: `hasVideo: true` のポストに、「動画」の札が付く (グリッド・リスト・ポスト表示・サイドパネルのそれぞれ)。画像が 2 枚以上のときだけ、枚数の札が付く。画像が 1 枚のポストと、メディアのないポストには、札が付かない。動画のポストには、枚数の札が付かない。`videoPoster` がない動画のポストは、暗い面と再生ボタンの表示になる。`hasVideo` が未定義のポストは、札が付かない。札に `aria-label` が付く。
- 10: サイドパネルで 1 件選ぶと、「N 件選択中」のボタンが出て、押すと 4 つの操作が開く。大きなボタンの縦並びが出ない。選択のたびに、一覧の位置がずれない。何も選ばないと、ボタンが出ない。
- A: カードの「…」メニューを、画面の端に近いカードで開いても、画面内に収まる (左端・右端・下端)。メニューが、カードの `overflow` に隠れない (メニューの親が、カードの内側にない)。Esc と外側のクリックで閉じる。
- B: 削除の確認の本文のスタイルに、折り返しを整える指定があり、確認の幅が、中身 2 行ぶんより狭くならない。

- サイドパネルで複数選択すると、「N 件選択中 ⌄」から、4 つの操作ができる。
